# Upgrading from 3.3 to 4.0

4.0 is a hard break with no compatibility layer. Almost nothing was deleted:
of the 885 names the root exported in 3.3.0, seventy-eight exist nowhere any more
and the rest simply live at a named address instead of a flat one. So most of the
work is an import sweep, and this page is mostly a map.

Read the first two sections and you can fix the imports. Read the third even
if you are in a hurry, because in four places, one of them only for code
written against 4.0.0rc1, the obvious fix is the wrong one, and three of those
four change a number without raising anything.

## The one rule: imports move down one level

In 3.3.0 the root re-exported the whole library, so `from phonometry import
laeq` worked for almost every name. Today the root exports twenty-five things:
the twenty-one subpackages, the three classes that belong to no single domain
(`Signal`, `ReportMetadata`, `PhonometryWarning`) and `__version__`.

```python
import phonometry

print(len(phonometry.__all__))          # 25
print("laeq" in phonometry.__all__)     # False

from phonometry.signals import laeq     # this is the new spelling
```

Measured across the whole surface, 804 of those 885 root names are published
today by exactly one subpackage, none by two, and none needs a path deeper
than `phonometry.<subpackage>`. Three more are still at the root, where they
always were. So the swap is unambiguous: find the subpackage, import from it.

The attribute form was never removed, which is the smallest possible diff for
code that reached through the root:

```python
from phonometry import filters

print(filters.nominal_frequencies(1).labels)
```

### Finding the new home of a name

Rather than search the reference for each one, ask the installed package:

```python
import importlib
import pkgutil

import phonometry


def whereis(name):
    """Every public module that publishes `name`, shallowest first."""
    found = ["phonometry"] if name in phonometry.__all__ else []
    for attribute in phonometry.__all__:
        package = getattr(phonometry, attribute)
        if not hasattr(package, "__path__"):
            continue
        modules = [package.__name__]
        modules += [m.name for m in pkgutil.walk_packages(package.__path__, package.__name__ + ".")]
        for module_name in modules:
            if any(part.startswith("_") for part in module_name.split(".")):
                continue
            try:
                module = importlib.import_module(module_name)
            except ImportError:
                continue
            if name in getattr(module, "__all__", ()):
                found.append(module_name)
    return sorted(found, key=lambda path: path.count("."))


print(whereis("laeq")[0])                  # phonometry.signals
print(whereis("reverberation_time")[0])    # phonometry.room
print(whereis("sensitivity")[0])           # phonometry.metrology
print(whereis("Signal")[0])                # phonometry
```

It walks the tree in about two seconds. When it returns several paths the
shallowest one is the canonical import: a subpackage re-exports what its own
modules publish, and that shallow path is the one the guides and the tests
use. The four names the root still publishes on its own, `Signal`,
`PhonometryWarning`, `ReportMetadata` and `__version__`, come back as
`phonometry` itself. An empty list means the name is in the last section of
this page.

## Modules that split rather than moved

Five of the thirty modules that changed path did not move to one new address.
They were divided, and a reader who follows only the first half of the split
gets an `ImportError` for the rest. These are worth checking one by one, and
the private renderer package is listed with them because the same thing
happened to it:

| 3.3.0 module | Where its contents are now |
| --- | --- |
| `phonometry.impedance_tube` | `materials.absorbers.impedance_tube` (two-microphone transfer function), `materials.absorbers.four_microphone` (`TransferMatrix`, `transfer_matrix_one_load`, `wave_decomposition`, `face_quantities`, `air_layer_transfer_matrix`), `materials.absorbers.standing_wave`, and `fluids` |
| `phonometry.scattering_diffusion` | `materials.diffusers.reverberation_room_scattering` for the reverberation-room part (`ScatteringResult`, `ScatteringUncertainty`, `BASE_PLATE_BANDS_HZ` and the rest), `materials.diffusers.scattering_diffusion` for the nine free-field names |
| `phonometry.materials.porous_absorber` | `materials.absorbers.porous` for the bulk-material models, `materials.absorbers.layered` for the whole multilayer API (`layered_absorber`, `AirLayer`, `MembraneLayer`, `PerforatedPlateLayer`, `MicroperforatedPlateLayer`, `LayeredAbsorberResult`) |
| `phonometry.metrology.spectra` | `signals.spectra`, plus `signals.multitaper` (`multitaper_psd`) and `signals.windows` (`window_metrics`) |
| `phonometry.compliance` | `filters.compliance` (`FilterComplianceResult`, `class_limits`, `verify_filter_class`), `filters.weighting_compliance` (`verify_weighting_class`, `weighting_class_limits`), `aircraft.measurement_system` (`verify_aircraft_noise_system`) |
| `phonometry._plotting` | `phonometry._plot.<domain>`: the 82 renderers were split per domain, so `plot_airborne_insulation` is in `_plot.building` and `plot_age_threshold` in `_plot.hearing`. Private either way, and `.plot()` on the result is the supported route |

The other twenty-five moved whole, and the resolver above finds them without
reading this table. Each of the first three was reachable by two paths in
3.3.0, the flat one and the one under its package, and both are gone.

## Four where the obvious fix is the wrong one

Everything else on this page announces itself the moment you run it, and the
fix is the one it looks like. These four are not that.

### The impedance-tube helpers took kelvin

`air_density_iso` and `speed_of_sound_iso` documented and consumed their
temperature in **kelvin**. Their successors take degrees Celsius, like the
rest of the library. The names changed, so the import fails and you will
notice, but the argument you carry over is the problem: 293.15 is a
legitimate-looking number in either unit.

```python
from phonometry.materials import speed_of_sound_iso10534

print(round(float(speed_of_sound_iso10534(temperature_c=20.0)), 5))      # 343.28784
print(round(float(speed_of_sound_iso10534(temperature_c=293.15)), 5))    # 477.13003
```

343.29 m/s against 477.13 m/s: a 39 % error, no exception, and every
absorption coefficient computed from it is wrong by a plausible-looking
amount. Convert the value, do not just rename the keyword.

| 3.3.0 | 4.0 |
| --- | --- |
| `impedance_tube.air_density_iso(T_kelvin, p_kPa)` | `materials.air_density_iso10534(temperature_c=T_kelvin - 273.15, static_pressure_kpa=p_kPa)` |
| `impedance_tube.speed_of_sound_iso(T_kelvin)` | `materials.speed_of_sound_iso10534(temperature_c=T_kelvin - 273.15)` |

With the conversion applied both return exactly what they returned in 3.3.0,
bit for bit.

### `GasStream` took kelvin

`noise_control.GasStream` held the inlet temperature of IEC 60534-8-3 as
`inlet_temperature_k` in 4.0.0rc1, in **kelvin**, the way Clause 5 reads it.
In 4.0 the field is `inlet_temperature_c`, in degrees Celsius like every other
temperature the library takes, and the conversion to the absolute temperature
Clause 5 needs happens inside. The keyword fails, so you will notice, but
450.0 is as legitimate a number in one unit as in the other: rename the
keyword and keep the number, and the gas is 273.15 K hotter. Annex A's
example 1 at 450 K puts 91.7 dB(A) at 1 m from the pipe; the same 450 read as
degrees Celsius puts 93.0 dB(A) there, and nothing raises.

| 4.0.0rc1 | 4.0 |
| --- | --- |
| `GasStream(inlet_temperature_k=T_kelvin, ...)` | `GasStream(inlet_temperature_c=T_kelvin - 273.15, ...)` |

### `speed_of_sound` is `speed_of_sound_iso17497`, not `fluids.air()`

The `speed_of_sound(temperature)` of 3.3.0, at the top level and in
`materials.scattering_diffusion`, is the ISO 17497-1 one-liner, and in 4.0 it
is `materials.speed_of_sound_iso17497`: the same formula and the same number,
with the temperature, still in degrees Celsius, written by name. The trap is
the other candidate. `fluids.air()` is where the rest of 4.0 reads the speed of
sound of the air from, so it looks like the new home of a function that
returned one, but it computes humid air by IEC 61094-2 Annex F: at 20 °C it
answers 343.99 m/s where the ISO 17497-1 formula answers 343.20 m/s, and
nothing raises. That is small, and it is not nothing if you are reproducing a
measurement made with the old number.

```python
from phonometry import fluids, materials

print(round(float(materials.speed_of_sound_iso17497(temperature_c=20.0)), 2))    # 343.2
air = fluids.air(temperature_c=20.0, relative_humidity_percent=50.0, static_pressure_pa=101_325.0)
print(round(air.speed_of_sound, 2))                                              # 343.99
```

| 3.3.0 | 4.0 |
| --- | --- |
| `speed_of_sound(T_celsius)` | `materials.speed_of_sound_iso17497(temperature_c=T_celsius)` |

### The `tl` field of an underwater result is `pl`

`transmission_loss` became `propagation_loss`, which the import catches, and
the field inside the result was renamed with it. That one does not raise: a
`PropagationLossResult` has no `.tl`, so the `AttributeError` arrives wherever
you read it, which may be far from the call.

```python
from phonometry.underwater.propagation.closed_form import propagation_loss

result = propagation_loss([1000.0], 1000.0)
print(round(float(result.pl[0]), 5))    # 60.06013, the number .tl used to hold
```

The same rename reaches `underwater.sonar_equation`, whose
`transmission_loss` parameter is now `propagation_loss`.

## The environment moved into a dataclass

Five entry points no longer take the ambient conditions as loose numbers.
Renaming the keyword is not enough there, because the parameter is gone
entirely:

| 3.3.0 | 4.0 |
| --- | --- |
| `airport_noise.event_level(..., temperature=15.0, pressure=101.325)` | `event_level(..., atmosphere=AerodromeAtmosphere(temperature_c=15.0, static_pressure_kpa=101.325))` |
| `airport_noise.noise_contour(...)` | the same, with `AerodromeAtmosphere` |
| `rotorcraft_noise.rotorcraft_event_level(..., temperature=15.0, relative_humidity=70.0)` | `rotorcraft_event_level(..., atmosphere=RotorcraftAtmosphere(temperature_c=15.0, relative_humidity_percent=70.0))` |
| `rotorcraft_noise.rotorcraft_noise_contour(...)` | the same, with `RotorcraftAtmosphere` |
| `outdoor_propagation.predicted_receiver_level(..., humidity=70.0)` | `predicted_receiver_level(..., atmosphere=AtmosphericConditions(relative_humidity_percent=70.0))` |

The other options of these functions went into records too, the per-point
rotorcraft overrides among them, and the next section maps them.

```python
from phonometry.aircraft.airport_noise import AerodromeAtmosphere

atmosphere = AerodromeAtmosphere(temperature_c=15.0, static_pressure_kpa=101.325)
print(atmosphere.temperature_c, atmosphere.static_pressure_kpa)
```

## The longest signatures take their options in records

Ten signatures took more than thirteen parameters each, and in 4.0 the
options that belong together are one record. A 3.3.0 keyword among them is
not renamed but gone, so a call that passes one raises `TypeError`: build the
record the keyword went into and pass that. Every field
of a record is written by name, and a field with a default has the default its
keyword had, so a record carries only what you change. The atmospheres of the
section above are records of the same kind; these are the rest:

| 3.3.0 | 4.0 |
| --- | --- |
| `filter_type=`, `ripple=` and `attenuation=` on `octave_filter` and `OctaveFilterBank`, and `resample=` on `OctaveFilterBank` | `design=filters.FilterDesign(filter_type=..., ripple=..., attenuation=..., resample=...)` |
| `calibration_factor=` and `dbfs=` on `octave_filter` and `OctaveFilterBank` | `calibration=filters.LevelCalibration(factor=..., dbfs=...)` |
| `show=` and `plot_file=` on `octave_filter` and `OctaveFilterBank` | `response_plot=filters.ResponsePlot(show=..., file=...)` |
| `stateful=` and `steady_ic=` on `OctaveFilterBank` | `block_processing=filters.BlockProcessing(stateful=..., steady_ic=...)` |
| `polar=`, `polar_frequency=` and `directivity_index_db=` on `microphone_characteristics` | `directivity=electroacoustics.MicrophoneDirectivity(polar=..., frequency=..., index=...)` |
| `noise_voltage=`, `equivalent_noise_level_db=`, `noise_weighting=` and `noise_spectrum=` on `microphone_characteristics` | `noise=electroacoustics.MicrophoneNoise(voltage_v=..., equivalent_level=..., weighting=..., spectrum=...)`, whose weighting is `"A"` or `"468"`, as the table of one spelling per concept says |
| `max_spl_db=`, `max_spl_thd_percent=` and `distortion=` on `microphone_characteristics` | `overload=electroacoustics.MicrophoneOverload(spl=..., thd_percent=..., distortion=...)` |
| `rated_impedance=`, `minimum_load_impedance=`, `powering=` and `supply_current_ma=` on `microphone_characteristics` | `electrical=electroacoustics.MicrophoneElectrical(rated_impedance_ohm=..., min_load_impedance_ohm=..., powering=..., supply_current_ma=...)` |
| `directivity=` (a `RadiatingPistonResult`), `polar=`, `polar_frequency=` and `directivity_index_db=` on `loudspeaker_characteristics` | `directivity=electroacoustics.LoudspeakerDirectivity(piston=..., polar=..., frequency=..., index=...)` |
| `rated_frequency_range=`, `rated_noise_power=`, `rated_sinusoidal_power=` and `resonance_frequency=` on `loudspeaker_characteristics` | `ratings=electroacoustics.LoudspeakerRatings(frequency_range=..., noise_power=..., sinusoidal_power=..., resonance_frequency=...)` |
| `absorption_area=`, `reverberation_time=`, `volume=`, `mean_absorption_coefficient=` and `room_surface=` on `sound_power_pressure` | `room=emission.RoomEnvironment(...)`, with the same five names |
| `distance`, `source_height` and `receiver_height` by position, and `projected_distance=`, on `predicted_receiver_level` | `environment.PropagationGeometry(distance=..., source_height_m=..., receiver_height_m=..., projected_distance=...)` as the second argument, after the sound power level |
| `ground_source=`, `ground_middle=` and `ground_receiver=` on `predicted_receiver_level` | `ground=environment.GroundFactors(source=..., middle=..., receiver=...)` |
| `directivity_index=` and `d_omega=` on `predicted_receiver_level` | `directivity=environment.DirectivityCorrection(index=..., d_omega=...)` |
| `ground_roll=`, `landing_roll=` and `bank=` on `aircraft.event_level` and `noise_contour` | `segments=aircraft.FlightSegmentState(ground_roll=..., landing_roll=..., bank=...)` |
| `atmospheric_method=` on `rotorcraft_event_level` and `rotorcraft_noise_contour` | the `atmospheric_method` of their `RotorcraftAtmosphere` |
| `receiver_height=`, `ground_elevation=`, `flow_resistivity=`, `terrain=` and `terrain_resolution=` on the same two | `ground=aircraft.RotorcraftGround(receiver_height_m=..., ground_elevation=..., flow_resistivity=..., terrain=..., terrain_resolution=...)` |
| `airspeed=`, `path_angle=`, `heading=` and `bank_angle=` on the same two | `track_state=aircraft.RotorcraftTrackState(airspeed=..., path_angle_deg=..., heading=..., bank_angle_deg=...)` |
| `scaling_factor=` and `triangles=` on the same two | `interpolation=aircraft.FlightConditionInterpolation(scaling_factor=..., triangles=...)` |

`OctaveFilterBank(48000, 3)` reads as it did, because the four arguments
callers write by position kept their places; on `octave_filter` every option
after `limits` is written by name.

```python
import numpy as np

from phonometry import filters

x = np.random.default_rng(0).standard_normal(48_000)
try:
    filters.octave_filter(x, 48_000, calibration_factor=2.0)
except TypeError as error:
    print(type(error).__name__)
# TypeError
result = filters.octave_filter(x, 48_000, calibration=filters.LevelCalibration(factor=2.0))
print(len(result.frequencies))
# 11
```

## The air of a model is one `fluid=`

Twenty-two functions of 3.3.0 took the air they compute in as loose numbers:
a speed of sound and a density, for the visco-thermal models a viscosity, a
Prandtl number, a ratio of specific heats and a static pressure, and for the
thermal correction of ISO 9053-2 a specific heat and a thermal conductivity,
each with a default of its own. In 4.0 these twenty-two take one `fluid=`, a
`fluids.Fluid` that carries every property its model reads, and their loose
keywords are gone, so a call that passed one raises `TypeError`. Other functions
that take a speed of sound or a density, `expansion_chamber` among them, keep
their own keywords. Left out, `fluid=` is
`materials.ABSORBER_AIR`, which holds the defaults 3.3.0 had: 343 m/s,
1.205 kg/m³, 1.84·10⁻⁵ Pa s, a Prandtl number of 0.71, a ratio of specific heats
of 1.4 and 101.325 kPa. A call that never passed the air gives the number it
gave.

| 3.3.0 | 4.0 |
| --- | --- |
| `speed_of_sound=` and `air_density=` on `delany_bazley`, `miki`, `membrane_resonance_frequency`, `mass_law_transmission_loss`, `single_panel_transmission_loss`, `double_wall_transmission_loss`, `mass_spring_mass_resonance`, `ground_effect` and `barrier_insertion_loss` | `fluid=` |
| `speed_of_sound=`, `air_density=` and `viscosity=` on `layered_absorber` and `diffuse_field_absorption`; `air_density=` and `viscosity=` on `perforated_plate_impedance` and `microperforated_plate_impedance` | `fluid=` |
| `speed_of_sound=`, `air_density=`, `viscosity=`, `prandtl_number=`, `heat_capacity_ratio=` and `atmospheric_pressure=` on `johnson_champoux_allard`, `slit_helmholtz_absorber` and `critical_coupling_design`, and the same less `speed_of_sound=` on `helmholtz_resonator_impedance`, `slit_effective_properties` and `rectangular_duct_properties` | `fluid=`, whose `static_pressure_pa` is the pressure, in pascals as before |
| `air_density=` on `atmospheric_parabolic_equation` | `fluid=` |
| `speed_of_sound=`, `air_density=`, `specific_heat_ratio=`, `specific_heat_cp=` and `thermal_conductivity=` on `effective_kappa`, and the same less `specific_heat_ratio=` on `thermal_boundary_layer_thickness` | `fluid=`, with another default, below |

Pass the air you mean as a `Fluid`. `fluids.air()` computes one at a
temperature, a humidity and a pressure, and a `Fluid` built by hand carries the
numbers a book prints. A model that reads a property the fluid does not carry
raises `fluids.FluidPropertyUnavailableError`, naming it.

```python
import numpy as np

from phonometry import fluids, materials

f = np.array([250.0, 1000.0])
print(materials.delany_bazley(f, 20_000.0).characteristic_impedance.round(1))
# [971.5-775.5j 609.6-281.1j]
book_air = fluids.Fluid(
    temperature_c=20.0,
    static_pressure_pa=101_325.0,
    composition={},
    model="the air of the book being reproduced",
    validity="",
    properties={"speed_of_sound": 340.0, "density": 1.21},
)
# delany_bazley(f, 20000.0, speed_of_sound=340.0, air_density=1.21) in 3.3.0
print(materials.delany_bazley(f, 20_000.0, fluid=book_air).characteristic_impedance.round(1))
# [965.3-769.6j 606.1-279.j ]
```

Two of the twenty-two take another air by default. `effective_kappa` and
`thermal_boundary_layer_thickness`, the thermal correction of ISO 9053-2,
defaulted in 3.3.0 to the five values ISO 9053-2 Annex A.3 prints, two of
which are not the air the annex says it uses ([errata register](https://docs.jmrp.io/phonometry/reference/errata/)).
In 4.0 they default to that air, IEC 61094-2 Annex F at the Annex A.3 state of
23 °C, 101.325 kPa and 50 % relative humidity. The correction moves in its
fifth figure, `effective_kappa(0.01, 0.001, 250.0)` is 1.400297 where it was
1.400339, and the printed Annex A.3 results still come out.

## A parameter that names a quantity carries its unit

Everywhere else, the ambient conditions kept their place and gained a suffix.
The rule is that a public parameter naming a dimensional quantity ends in the
unit the caller types, because a number is where a unit is lost and no guard
can catch it by magnitude: 101.325 and 101325 are both legitimate pressures
in this library.

| 3.3.0 | 4.0 |
| --- | --- |
| `temperature=` | `temperature_c=` |
| `pressure=` on `air_attenuation`, `air_attenuation_m` (now `air_power_attenuation_per_m`), `atmospheric_attenuation`, `atmospheric_absorption`, `outdoor_propagation_attenuation`, `sae_band_attenuation` (now `band_attenuation_arp5534`), `impedance_adjustment` and `atmospheric_adjustment`, and on the `event_level` and `noise_contour` methods of `AnpAircraft` and `AnpDatabase`; `static_pressure=` on `meteorological_corrections`, `sound_power_anechoic`, `sound_power_reverberation` and `sound_power_comparison`; the fields `AtmosphericAttenuation.pressure`, `AircraftBandAttenuation.pressure` and `ReportMetadata.pressure`, all in kPa | `static_pressure_kpa=` and `.static_pressure_kpa` |
| `static_pressure=` on `alternating_airflow_resistance`, `barometric_pressure=` on `sound_power_intensity_precision`, `atmospheric_pressure=` on `enclosed_gas_stiffness` and `floating_floor_resonance` | `static_pressure_pa=` |
| `atmospheric_pressure=` on `air_density_iso` (now `air_density_iso10534`) and `air_density_astm` (now `air_density_astm_e2611`) | `static_pressure_kpa=` on `air_density_iso10534` and `air_density_astm_e2611` |
| `atmospheric_pressure=` on `johnson_champoux_allard` and the slow-sound functions | the `fluid=` they take now, which carries its own static pressure |
| `humidity=`, `relative_humidity=` | `relative_humidity_percent=` |
| `diameter=` and its thirteen compounds | `diameter_m=` |
| `angle=`, `angles=`, `bank_angle=`, `path_angle=`, `grazing_angle=`, `launch_angles=` | `_deg=` or `_rad=`, whichever the function reads |
| `runway_gradient=` | `runway_gradient_ratio=` |
| `sound_speed_gradient=` | `sound_speed_gradient_per_s=` |

The pressure of the medium has one name. `static_pressure_kpa` or
`static_pressure_pa` is the absolute pressure of the medium a quantity is
computed in (the air, a gas or sea water), in the unit its clause writes it in; a stream pressure measured
in a duct is a gauge pressure and says so (`static_gauge_pressure_pa`), or is
the `static_pressure_pa` of `velocity_pressure_pa` and `total_pressure`, whose
formulas read it that way. `atmospheric_pressure_pa` is kept only for the
outside atmosphere where the same method measures a stream pressure beside it:
`pipe_transmission_loss`, `DownstreamPipe`, `normal_air_density` and
`gas_density_kg_m3`.

One case is worth naming because it was a trap rather than an inconvenience.
`critical_angle` was a field in radians on one result and a parameter in
degrees on the two functions one screen below it, which is the same word for
two things 57 times apart. It is `critical_angle_rad` on the result and
`critical_angle_deg` on the parameters now.

`transmission_loss=` became `propagation_loss=` only in the underwater sonar
and numerical-propagation results. `ReactiveSilencerResult` and
`SoundReductionResult` still call theirs `transmission_loss=`, correctly:
that is what the standards behind them call it.

The EN 29052-1 functions of `materials` follow the same rule, with the unit
of each quantity at the end of its name:

| 3.3.0 | 4.0 |
| --- | --- |
| `apparent_dynamic_stiffness(resonant_frequency=, total_mass_per_area=)` | `resonant_frequency_hz=`, `total_mass_per_area_kg_m2=` |
| `enclosed_gas_stiffness(thickness=)` | `thickness_m=` |
| `installed_dynamic_stiffness(apparent_stiffness, airflow_resistivity, gas_stiffness=)` | `apparent_stiffness_n_m3`, `airflow_resistivity_kpa_s_m2=` by name only, `gas_stiffness_n_m3=` |
| `natural_frequency(dynamic_stiffness=, mass_per_area=)` | `dynamic_stiffness_n_m3=`, `mass_per_area_kg_m2=` |
| `floating_floor_resonance(resonant_frequency=, total_mass_per_area=, floor_mass_per_area=, airflow_resistivity=, thickness=)` | `resonant_frequency_hz=`, `total_mass_per_area_kg_m2=`, `floor_mass_per_area_kg_m2=`, `airflow_resistivity_kpa_s_m2=`, `thickness_m=` |

The airflow resistivity is the one that earns the keyword. EN 29052-1
thresholds it in kPa·s/m², and every other flow resistivity in the library is
in Pa·s/m², a unit a thousand times smaller, so a Pa·s/m² figure passed by
position landed in the wrong branch of clause 8.2 without a word; it is
written by name now. And below 100 kPa·s/m², `installed_dynamic_stiffness` no
longer reads a missing gas term as zero: 3.3.0 returned $s'_\mathrm{t}$ from
`installed_dynamic_stiffness(20e6, 50.0)`, Formula 6 with its second term
dropped, and 4.0 raises and asks for $s'_\mathrm{a}$.

The ISO 13472-1 functions of `materials` spell the microphone out and give
both heights in metres, and two temperatures say which scale they are on:

## Conditions and flags are written by name

An ambient or medium condition or a calibration factor that carries a default,
and every public boolean flag, are keyword-only. The conditions are the
temperature, the humidity and the static pressure, the speed of sound and the
density of the medium, and the three ground factors of ISO 9613-2. The rule exists because the call site is
where the meaning is lost: `air_attenuation(freqs, 20.0, 50.0, 101.325)` is a
temperature, a humidity and a pressure in an order nobody remembers, and
`bank.filter(x, True)` says nothing about which of five flags was thrown. A
choice of method or of band set and a count (`mode`, `method`, `fraction`,
`n`, `seed`) are options, not conditions, and the rule leaves them where they
are.

The failure is loud, which is the point:

```python
import numpy as np

from phonometry.signals import leq

x = np.random.default_rng(1).standard_normal(4800) * 0.01

try:
    leq(x, 48000)
except TypeError as error:
    print(error)      # leq() takes 1 positional argument but 2 were given
```

That call is worth a second look. `leq` never had an `fs`, because an energy
average does not need one, so in 3.3.0 the 48000 silently bound to
`calibration_factor` and the answer came back 93.6 dB high with no complaint.
Now it is a `TypeError`, which is what it always should have been.

```python
print(round(float(leq(x, dbfs=True)), 3))
```

A frequency axis is written by name as well, wherever it sits beside the values
it labels. Two arrays of one length bind either way round without a complaint,
so a call that swaps them answers on the wrong axis instead of failing; the API
reference itself carried `weighted_rating_extended(freqs, r)` and
`weighted_impact_rating_extended(freqs, ln)` with the frequencies where the
levels go. The values stay positional, in the order they
had, and the axis goes behind the `*`:

```python
import numpy as np

from phonometry import room, signals

frequencies = np.array([63.0, 125.0, 250.0, 500.0, 1000.0, 2000.0, 4000.0, 8000.0])
levels = np.array([62.0, 56.0, 50.0, 45.0, 41.0, 38.0, 36.0, 35.0])

print(room.noise_criterion(levels, frequencies=frequencies).rating)
smoothed = signals.fractional_octave_smoothing(levels, frequencies=frequencies, domain="db")
print(smoothed.shape)

try:
    room.noise_criterion(levels, frequencies)
except TypeError as error:
    print(error)      # noise_criterion() takes 1 positional argument but 2 were given
```

`critical_frequencies` beside the vibration reduction indices of ISO 12354-1.

## One spelling per concept

The public names had drifted into several spellings of the same quantity, and
4.0 keeps the one the majority already used. The rule for the quantities
counted in the plural is the one most of the API followed: a field or a
parameter that holds an array is `frequencies`, `times`, `distances` or
`levels`, and one that holds a single value is singular. A vectorised argument
that takes either a number or an array keeps its name. An axis carries no
unit in its name, because its unit never changes: `frequencies` are in
hertz, `levels` in decibels and the sample rate is `fs` on every function.

## A function is named for what it returns, once

## A level or a level difference carries no unit suffix

A level and a level difference are in decibels by definition (a loudness level
is in phon), so a public name whose head noun is one carries no `_db`, whether
it is a parameter, a field, a property, a method or a constant. The head noun
is the last noun of the name, past the words that qualify it from behind (a
band, a frequency weighting, `before` or `after`, `max` or `min`): a level, a
loss, an insulation, an isolation, a reduction, a rejection, a difference, an
improvement, a single-value attenuation, a correction, an adjustment, an
index, the spectrum adaptation term of ISO 717, a shift or an excess of the
level the name names (`level_shift`), or the printed symbol of one of them. A
name whose head noun does not say decibel keeps the suffix: a tolerance, a
margin, an uncertainty, a deviation, a step, a slope or a rate
(`tolerance_db`, `background_margin_db`, `expanded_uncertainty_db`,
`slope_db_per_decade`, `attenuation_db_per_m`). A notebook table still shows
a number under such a name in decibels, now read from its head noun, and a
loudness level in phon; a flag, a text, a complex factor or a record under
one shows no unit, and a number the head noun would misread (the reflection
index of EN 1793-5, the A_eta of IEC 60534-8-3) shows its own. Most of the
names this renames are newer than 4.0.0rc1; the ones that shipped are these.

## A name says the quantity it holds

A name that put `_db` after words that only qualify it (`corrected_db`,
`floor_db`, `threshold_db`, `mean_db`) said the unit of a number and never
what the number is. Each now carries the noun of what it holds. A level takes
`level` or `levels` and then loses its `_db` by the rule of the section above
(`threshold_level`, `corrected_levels`, `emission_levels`), a level

## A module is never hidden behind a function of its own name

Twenty-three modules of 4.0.0rc1 shared their name with the function their
package published: `signals/correlation.py` sat beside `signals.correlation()`.
The package attribute is the function, so `import
phonometry.signals.correlation as m` bound the function,
`signals.correlation.time_delay` raised `AttributeError`, and only `from
phonometry.signals.correlation import time_delay` reached the module. Each of
those modules is private now. The function keeps its name, every name the

the import through the file path:

Every result's `.plot()` now reads `plot(ax=None, *, ...)`: the axes first,
and every other argument by name, `language` included. Three did not start
with the axes in 3.3.0, so `plot(ax)` on them handed the axes to the wrong
parameter:

| 3.3.0 | 4.0 |
| --- | --- |
| `LoudspeakerCharacteristics.plot("impedance", ax)` | `.plot(ax, quantity="impedance")` |
| `MicrophoneCharacteristics.plot("noise", ax)` | `.plot(ax, quantity="noise")` |

The public `plot_*` helpers, which draw a device or a geometry rather than a

## A multi-panel `.plot()` returns a tuple of axes

A `.plot()` that draws more than one panel returns, without `ax`, a tuple of
its axes, the top panel first, where 3.3.0 and 4.0.0rc1 returned a NumPy
array of them. Indexing, unpacking and `len()` work as before; the array's
own attributes do not:

| 3.3.0 or 4.0.0rc1 | 4.0 |
| --- | --- |
| `axes = result.plot()`, then `axes.shape` or `axes.size` | `len(result.plot())` |
| `result.plot().flat`, `result.plot().ravel()` | the tuple itself: `for ax in result.plot()` |
| `isinstance(drawn, np.ndarray)`, to tell several panels from one axes | `isinstance(drawn, tuple)` |

With `ax` the plot draws one panel on it and returns that axes, as before.
Each case is a typed overload now, so a type checker reads
`top, bottom = result.plot()` as two `Axes` and `result.plot(ax=ax)` as one.
`ZwickerLoudness.plot()` without `ax` still returns one axes for a stationary
result and two for a time-varying one, which only the data decide.

The plots that draw on a polar axes say so. `PistonDirectivity`,
`VectorChangeResult` and `DiffuserPolarResponse` return a `PolarAxes`, and so
do `DiffusionResult.plot()` without `ax`, `DirectivityFactor.plot()` for its

`MicrophoneCharacteristics.plot()` for `quantity="directivity"`. Those take a

`projection="polar"` as plain `Axes`, so a typed caller hands it over as
`typing.cast(PolarAxes, ax)`. `DiffuserPolarResponse.plot()` refuses a
cartesian axes with a `ValueError` that names `ax`, as the other polar plots
do, where it raised an `AttributeError` from matplotlib.

## A zero-dimensional array gives a zero-dimensional array

A function of a number or an array of them returns a `float` only when every
argument that decides the shape of its result is a number, a Python or a
NumPy one, and an array as soon as one of them is a sequence or an array,
where 3.3.0 and 4.0.0rc1 returned a `float` for a zero-dimensional array.
Ninety public functions and methods follow the rule, `room.room_constant`,
`room.critical_distance` and `fluids.sea_water_sound_speed` among them, and
`vibration.evaluation_zone` follows it with a zone letter where the others
give a `float`:

| 3.3.0 or 4.0.0rc1 | 4.0 |
| --- | --- |
| `room.room_constant(100.0, np.array(0.2))` returned the `float` `25.0` | it returns `array(25.)`; `float(...)` or `.item()` gives the number |
| `emission.local_environmental_correction([0.5])` returned a `float` for any one-element input, as did `emission.environmental_ratio_from_k2`, `emission.environmental_ratio_from_absorption`, and the `background_margin_db` field and the `correction` property of the `WorkstationBackgroundCorrection` that `emission.background_noise_correction_at_workstation` returns | each gives a one-element array; hand over `0.5`, not `[0.5]`, to get a number |
| `electroacoustics.piston_resistance(1.0)` returned a `numpy.float64`, as did `piston_reactance` and `piston_directivity` | it returns a Python `float`, with no `.shape` or `.dtype` |

Sixty-six of them gain typed overloads, so a type checker reads
`room.room_constant(100.0, 0.2)` as a `float` and
`room.room_constant(100.0, alphas)` as an array whatever the shape of
`alphas`; an `ArrayLike` or a nested list reads as the union, which a typed
caller narrows. The reducers (`signals.leq` and the other levels of a signal,
`building.energy_average_level`, `room.directivity_energy_average` and their
kin), whose result is one number for a one-dimensional input, keep the union
and their behaviour.

## A sample rate is a `float`, and a count takes a NumPy integer

The rate of a `Signal` is the `float` it was given, so a type checker reads
`sig.fs` as a `float`, where it read an `int`, and every function that runs
at any positive rate takes a `float`: the rate one function returns is the
rate the next one takes. The functions that need a whole number of samples
per second keep refusing a fractional one: `io.write`, which writes the rate
into the file's header, the test signals of `electroacoustics`,
`electroacoustics.field_strength_meter`, `room.image_source_rir`,
`psychoacoustics.loudness_zwicker`, `psychoacoustics.sharpness_din`,
`psychoacoustics.psychoacoustic_annoyance_from_signal` and `speech.stoi`.
`vibration.evaluate_train_passage`, `signals.resample_signal` handed a Signal
and the Method B bank of `environment` refused a fractional rate as well, on
the grounds that the filter bank needed a whole one, which it does not: they
run at any rate.

| 3.3.0 or 4.0.0rc1 | 4.0 |
| --- | --- |
| `psychoacoustics.loudness_zwicker(x, sig.fs)` type checked, `sig.fs` read as an `int` | hand over the Signal, `loudness_zwicker(sig)`, or `int(sig.fs)` |
| `io.write(path, io.Signal(x, 44100.5))` failed inside the header with `struct.error` | it raises `ValueError` naming `fs`, as `fs=44100.5` does |
| `filters.OctaveFilterBank(fs, order=2.5)`, `room.mls_signal(10.5)` and the other counts checked only as one number ran with a fraction or a bool | a fraction raises `ValueError: 'order' must be a whole number`, a bool a `TypeError`; pass the whole number |
| `emission.sound_intensity(p1, p2, fs, spacing_m=d, fraction=1.0)` ran | it raises `TypeError`, as every band fraction does; pass `1` or `3` |

A count, a band fraction or a flag takes the NumPy integer or truth value
its validator takes (`int | np.integer[Any]`, `BandFraction |
np.integer[Any]`, `bool | np.bool_`), and values by band take a mapping keyed
by integers (`{125: 40.0}`) as they take one keyed by floats. A count that
was checked only as one number is read by the same whole-number check, so a
fraction or a bool it used to take is refused, as in the rows above. A result
record that validates a count or a band fraction holds the `int` it reads,
where it kept a NumPy integer as it was given.

## Verdicts are result objects, not dictionaries

The three `verify_*` functions of 3.3.0 returned `dict[str, Any]` and now
return a frozen dataclass, like every other result in the library.
`filter_class_compliance`, the public wrapper that existed only to package the
filter verdict, went with the change, since the verifier now returns the
object itself. Each key of the dictionary is an attribute of the same name,
but for `passed`, which is `passes`, and every argument after the one the call
is about is written by name.

| 3.3.0 | 4.0 |
| --- | --- |
| `verify_filter_class(bank)["overall_class"]` | `filters.verify_filter_class(bank).overall_class` |
| `verify_filter_class(bank, 4096)` | `filters.verify_filter_class(bank, n_points=4096)` |
| `verify_weighting_class(wf)["overall_class"]` | `filters.verify_weighting_class(wf).overall_class` |
| `verify_aircraft_noise_system(...)["passed"]` | `aircraft.verify_aircraft_noise_system(...).passes` |
| `filter_class_compliance(bank)` | `filters.verify_filter_class(bank)`, which returns the same `FilterComplianceResult` |

`verify_intensity_class` and `verify_quasi_peak_dynamics` are newer than
3.3.0, and in 4.0.0rc1 they already returned their records.

```python
from phonometry.filters import OctaveFilterBank, verify_filter_class

verdict = verify_filter_class(OctaveFilterBank(48000, fraction=1, limits=[125, 4000]))
print(verdict.overall_class, len(verdict.bands))
```

`verify_running_rms_decay` is newer than 3.3.0, and in 4.0.0rc1 it returned a
bare `bool`, which threw away the printed interval and the measured time it
had judged. It now returns a `RunningRMSDecayVerification` that keeps both:
the verdict is `.passes`, beside `.measured_time_s`, `.printed_time_s`,
`.tolerance_s` and the interval as `.lower_time_s` and `.upper_time_s`. The
object refuses to be read as a truth value, so an
`if verify_running_rms_decay(...):` written against the release candidate
raises `TypeError` instead of passing every meter.

## A verdict says `passes`, refuses a truth value, and comes from a verb

A judgement is named for what it judges: `verify_` an instrument, `assess_` a
measured situation, `check_` the setup a method needs. Each returns a record
that keeps its reasons, and a pass or a fail is spelled `passes` on every one of
them. A record a judging function returns, and every record with a `passes`,
refuses to be read as a truth value: `if verdict:` raises `TypeError` and the
message names what to read. In 3.3.0 and 4.0.0rc1 these records were always
true, so an `if` written against them passed every failure: read `.passes` on
`QuasiPeakDynamicsResult`, `AircraftSystemComplianceResult`,
`WeightingVerification`, `PhaseVerification`, `SignalBurstVerification`,
`DBHRCheck`, `DBHRAssessment`, `ActivityAssessment` and `PeriodAssessment`;
`.overall_class` on `FilterComplianceResult`, `WeightingComplianceResult` and
`IntensityInstrumentComplianceResult`; `.within_guideline` on
`DamageAssessment`, since exceeding a guideline value of DIN 4150-3 is not a
failure; `.qualified` on `PrecisionCriteria`; `.adjustment` on
`TonalAssessmentResult`; and `.decisive_audibility` or `.audible` on
`ToneAudibilityResult`.

| 3.3.0 or 4.0.0rc1 | 4.0 |
| --- | --- |
| `.complies` on `DbHrCheck`, `DbHrAssessment` (now `DBHRCheck`, `DBHRAssessment`), `ActivityAssessment` and `PeriodAssessment` | `.passes` |
| `vibration.is_significant_change(change, zone_b_upper)` | `vibration.assess_operational_change(change, zone_b_upper).significant`, beside the `.threshold` it is read against. A significant change is a reason to investigate, not a failure, so the flag keeps its name |
| `materials.limp_frame_applicable(k_c, criterion=...)` | `materials.check_limp_frame(k_c, criterion=...).passes`, beside the `.ratio` and the `.threshold`. A ratio exactly on the threshold no longer passes: Allard & Atalla print both criteria as strict inequalities |
| `fi.field_is_stationary(limit=...)` on a `FieldIndicators` | `fi.check_field_stationarity().passes`, and band by band its `.stationary`. The limit is the 0.6 of Table B.3, read as `.limit`, and no longer an argument |
| `room.perceptibly_different(symbol, first, second)` | `room.assess_perceptible_difference(symbol, first, second).different`; the two values must now have the same shape |
| `materials.check_base_plate_scattering(s) == ()` | `materials.check_base_plate_scattering(s).passes`, with the bands over the limit in `.exceeded_frequencies` and the per-band `.margins`, `.exceeds` and `.limits` beside them. A coefficient that is not finite raises `ValueError`, where it used to pass |
| `corrected, limited = building.background_corrected_level(lp, lb)` | `result = building.background_corrected_level(lp, lb)`, then `result.corrected_levels` and `result.limited` |
| `k1, held = emission.background_noise_correction_at_workstation(lp, lb)` | `result = emission.background_noise_correction_at_workstation(lp, lb)`, then `result.correction` and `result.upper_bound` |

The 3.3.0 top-level names this renames (`rigid_mass_calibration_check`,
`satisfies_lower_requirement`, `satisfies_upper_requirement`,
`strong_coupling_satisfied` and `tonal_seeking_survey`) are in the table of
the names that are gone, at the end of this page.

```python
from phonometry import building, materials

conformity = building.assess_requirement_conformity(52.0, 1.5, 50.0, bound="minimum")
print(conformity.passes, conformity.margin_db)
# True 0.5
check = materials.check_base_plate_scattering([0.02] * len(materials.BASE_PLATE_BANDS_HZ))
print(check.passes, check.exceeded_frequencies.size)
# True 0
try:
    bool(check)
except TypeError as error:
    print(type(error).__name__)
# TypeError
```

## The filter bank returns a result, not a tuple

`octave_filter()` and `OctaveFilterBank.filter()` returned two items normally
and three when `sigbands=True` asked for the band waveforms. The length of the
answer depended on a keyword, which is why the pair needed twelve `@overload`
declarations to be typed at all, and why `_, _, bands = bank.filter(...)` was
a line you had to count commas in.

They now return an `OctaveFilterResult` with named fields. The other answers
of the bank that were tuples are records too: the spectrogram is an
`OctaveSpectrogramResult`, and the band set the bank is designed on is read
from attributes spelled out in full.

| 3.3.0 | 4.0 |
| --- | --- |
| `spl, freq = octave_filter(x, fs)` | `r = octave_filter(x, fs)`, then `r.levels` and `r.frequencies` |
| `spl, _ = octave_filter(x, fs)` | `octave_filter(x, fs).levels` |
| `_, freq = octave_filter(x, fs)` | `octave_filter(x, fs).frequencies` |
| `_, _, bands = bank.filter(x, sigbands=True)` | `bank.filter(x, sigbands=True).require_bands()` |
| `levels, freq, times = bank.spectrogram(x)` | `r = bank.spectrogram(x)`, then `r.levels`, `r.frequencies` and `r.times` (an `OctaveSpectrogramResult`, drawn with `r.plot()`) |
| `bank.freq`, `bank.freq_d`, `bank.freq_u`, `bank.nominal_freq`, `bank.num_bands` | `bank.frequencies`, `bank.lower_edges`, `bank.upper_edges`, `bank.labels`, `bank.n_bands`, read-only: the arrays refuse writes and `labels` is a tuple |

```python
import numpy as np
from phonometry import filters

result = filters.octave_filter(np.zeros(8000) + 1e-6, 8000, fraction=3)
print(len(result.frequencies), result.bands)
# 25 None
```

`bands` is `None` unless the call asked for `sigbands=True`, and `levels` is
`None` for a call made with `calculate_level=False`. Code that needs either
one can say so with `require_bands()` or `require_levels()`, which return the
value or raise naming the argument that was missing, rather than handing back
a `None` that fails several lines later.

The result also draws itself, so the band spectrum is one call:

```python
ax = result.plot()
```

## Other answers that were tuples are records

Every other answer that came back as a tuple of different quantities, to be
unpacked by position, is a record with named fields now, and none of them
unpacks: a line that still does raises `TypeError: cannot unpack
non-iterable ...` instead of handing back the wrong column. A tuple is left
only where its items are alike, such as the two ends of a range, lower
first.

| 3.3.0 or 4.0.0rc1 | 4.0 |
| --- | --- |
| `freq, lower, upper, labels = filters.nominal_frequencies(3)` | `b = filters.nominal_frequencies(3)`, then `b.frequencies`, `b.lower_edges`, `b.upper_edges` and `b.labels` (a `FractionalOctaveBands`) |
| `epnl, pnltm, kf, kl = aircraft.epnl_from_pnlt(pnlt)` | `r = aircraft.epnl_from_pnlt(pnlt)`, then `r.epnl`, `r.pnltm`, `r.band_limits` (the pair `(kF, kL)`), `r.bandsharing_adjustment` and `r.duration_correction` (an `EPNLIntegration`) |
| `freqs, delta_l = building.improvement_octave_bands(dl, f)` | `s = building.improvement_octave_bands(dl, frequencies=f)`, then `s.frequencies` and `s.values` (an `OctaveBandSpectrum`, whose `quantity` says what the values are) |
| `freqs, values = result.octave_bands()` on a `building.FloorCoveringImprovementResult` | `result.octave_bands().frequencies` and `.values`, the same `OctaveBandSpectrum` |
| `l_in, s_m = building.combine_subareas(l_in, areas)` | `r = building.subarea_intensity_level(l_in, areas)`, then `r.levels` and `r.measurement_area` (a `SubareaIntensityLevel`) |
| `freqs, u = band_uncertainty.to_arrays()` on a `building.BandUncertainty` | `band_uncertainty.frequencies` and `band_uncertainty.uncertainties`, the fields it was read from |
| `bx, bz, bxz = building.corrugated_plate_stiffness(...)` | `b = building.corrugated_plate_stiffness(...)`, then `b.b_x_n_m`, `b.b_z_n_m` and `b.b_xz_n_m` (a `CorrugatedPlateStiffness`) |
| `f, lower, upper = building.heavy_impact_source_limits(source)` | `lim = building.heavy_impact_source_limits(source)`, then `lim.frequencies`, `lim.lower` and `lim.upper` (a `HeavyImpactSourceLimits`) |
| `width, k = building.wall_tie_stiffness(tie)`, `building.WALL_TIE_STIFFNESS[tie][1]` | `t = building.wall_tie_stiffness(tie)`, then `t.cavity_width_m` and `t.stiffness` (a `WallTieStiffness`, which is also what each row of `WALL_TIE_STIFFNESS` holds) |
| `result.ratings` on a `building.LiningImprovementResult` | `result.delta_rw`, `result.delta_ra` and `result.delta_ratr`, the fields the tuple was read from |
| `f, gamma2 = electroacoustics.coherence(x, y, fs)` | `c = electroacoustics.coherence(x, y, fs)`, then `c.frequencies` and `c.coherence` (a `CoherenceResult`, with `.plot()`) |

| `f, class_1, class_2 = emission.residual_index_limits(device)` | `lim = emission.residual_index_limits(device)`, then `lim.frequencies`, `lim.class_1` and `lim.class_2` (a `ResidualIndexLimits`) |
| `wavelengths, levels = environment.wheel_roughness(brake)`, and the same of `rail_roughness`, `contact_filter` and `impact_roughness_single` | `w = environment.wheel_roughness(brake)`, then `w.wavelengths_mm` and `w.levels` (a `WavelengthSpectrum`, with `.plot()`) |

## Tolerance limits come lower first, and signed

`vibration.weighting_tolerance_percent` returned the Table 5 band of
ISO 8041-1 as `(upper, lower)`, and the three constants
`CENTRAL_TOLERANCE_PERCENT`, `SKIRT_TOLERANCE_PERCENT` and
`TAIL_TOLERANCE_PERCENT` held `(upper %, lower %, phase °)`. Every other pair of
limits in the library is `(lower, upper)`, so these two now are too. The lower
limit stays negative, as the table prints it, and `-100.0` still means that
the standard sets no lower limit.

This one changes no name and raises nothing: `upper, lower = ...` still
unpacks two arrays, and swaps them. Read every unpacking of the four:

| 4.0.0rc1 | 4.0 |
| --- | --- |
| `upper, lower = vibration.weighting_tolerance_percent(name, f)` | `lower, upper = vibration.weighting_tolerance_percent(name, f)` |
| `vibration.CENTRAL_TOLERANCE_PERCENT == (12.0, -11.0, 6.0)` | `(-11.0, 12.0, 6.0)` |
| `vibration.SKIRT_TOLERANCE_PERCENT == (26.0, -21.0, 12.0)` | `(-21.0, 26.0, 12.0)` |
| `vibration.TAIL_TOLERANCE_PERCENT == (26.0, -100.0, inf)` | `(-100.0, 26.0, inf)` |

```python
from phonometry import vibration

lower, upper = vibration.weighting_tolerance_percent("Wk", [16.0])
print(lower, upper)
# [-11.] [12.]
```
