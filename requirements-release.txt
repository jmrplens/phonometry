# The tools the release workflow (.github/workflows/release.yml) builds, checks
# and describes the published files with, pinned exactly like every other
# requirements file here, so Dependabot moves them in a pull request that runs
# a rehearsal instead of a release picking up whatever came out that morning.
#
# - build: the sdist, then the wheel from the sdist.
# - setuptools: the build back end itself. scripts/build_release.py builds
#   with --no-isolation, so the release, a rehearsal and anyone rebuilding a
#   release from its tag (SECURITY.md) all use this one version rather than
#   whatever setuptools is newest on the day, and get the same bytes.
#   pyproject.toml keeps the measured floor, so a distribution packager is not
#   bound to this pin.
# - trove-classifiers: the list of classifiers PyPI takes. setuptools holds
#   the classifiers of pyproject.toml to it only when it is installed, and
#   PyPI refuses an unknown one only at the upload, which a rehearsal never
#   makes; with it, the build refuses one, in a rehearsal and on every pull
#   request.
# - twine: `twine check --strict`, the long description PyPI will render.
# - check-wheel-contents: a wheel with stray or duplicated files.
# - cyclonedx-bom: the SBOM of the environment `pip install phonometry` makes.
#   Everything it installs is pinned below, because cyclonedx-python-lib
#   writes its own version into the SBOM: unpinned, the SBOM of one release
#   written again a week later could differ by that line alone.
#   scripts/release_sbom.py refuses an SBOM written by a tool at any other
#   version than the one pinned here.
#
# The upload itself is pypa/gh-action-pypi-publish, not twine: it holds the
# trusted-publishing exchange and writes the PEP 740 attestations.
