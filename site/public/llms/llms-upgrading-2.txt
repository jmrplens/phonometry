## A module is never hidden behind a function of its own name

Twenty-three modules of 4.0.0rc1 shared their name with the function their
package published: `signals/correlation.py` sat beside `signals.correlation()`.
The package attribute is the function, so `import
phonometry.signals.correlation as m` bound the function,
`signals.correlation.time_delay` raised `AttributeError`, and only `from
phonometry.signals.correlation import time_delay` reached the module. Each of
those modules is private now. The function keeps its name, every name the
package published from the module keeps its address, and the only thing gone is
the import through the file path:

| 4.0.0rc1 | 4.0 |
| --- | --- |
| `from phonometry.signals.correlation import time_delay` | `from phonometry.signals import time_delay` |
| `from phonometry.fluids.air import air` | `from phonometry.fluids import air`, or `fluids.air(...)` after `from phonometry import fluids` |
| `broadcast.program_loudness`, `emission.sound_power_anechoic`, `emission.sound_power_in_duct`, `emission.sound_power_in_situ`, `emission.sound_power_intensity`, `emission.sound_power_intensity_points`, `emission.sound_power_reverberation`, `fluids.air`, `materials.absorbers.airflow_resistance`, `noise_control.duct_path`, `psychoacoustics.quality.fluctuation_strength`, `psychoacoustics.quality.fluctuation_strength_ecma`, `psychoacoustics.quality.roughness_ecma`, `psychoacoustics.quality.tonality_ecma`, `psychoacoustics.quality.tone_audibility`, `room.crowd_noise`, `room.impulse_response`, `signals.cepstrum`, `signals.correlation`, `signals.envelope`, `underwater.propagation.seabed_reflection`, `vibration.structural.junction_transmission`, `vibration.structural.radiation_efficiency` as module paths | the package before the last dot, which publishes the function and its companions: `from phonometry.room import impulse_response, mls_impulse_response` |
| the numbers those modules kept for themselves: the gates and block lengths of `broadcast.program_loudness` (`ABSOLUTE_GATE`, `RELATIVE_GATE`, `BLOCK_DURATION`, `BLOCK_OVERLAP`, `SHORT_TERM_DURATION`, `MAX_METER_STEP`, `LRA_RELATIVE_GATE`, `LRA_PERCENTILES`), `DEFAULT_SELF_NOISE_FLOOR` of `noise_control.duct_path`, and `SIGMA_NARROWBAND_LEVEL` and `COVERAGE_FACTOR_90` of `psychoacoustics.quality.tone_audibility` | not published, as before: their packages never took them up. Each comes from the document its module follows, and the function that reads it applies it or takes it as the default of `self_noise_floor=`, `sigma_level_db=` or `coverage_factor=`. The 0.1 s step is the period of the 10 Hz update rate EBU Tech 3341 requires, and the 0 dB floor is the default of the worked duct-path sheet in Long's *Architectural Acoustics* |
| the prominence thresholds `PROMINENT_TONALITY_TU_HMS`, `PROMINENT_ROUGHNESS_ASPER` and `PROMINENT_FLUCTUATION_STRENGTH_VACIL` of the ECMA-418-2 modules | not published, and no function applies them: compare the result yourself. ECMA-418-2 clause 6.3 calls a tonality prominent when, for a stationary sound, `specific_tonality` exceeds 0.4 tu_HMS at a local maximum whose entry in `tonal_frequencies` lies between the centre frequencies one Bark_HMS below and above, or, for a non-stationary sound, when `tonality` exceeds 0.4 tu_HMS. Clause 7.2 calls a roughness prominent when `roughness` exceeds 0.2 asper, and clause 9.2 a fluctuation strength when `fluctuation_strength` exceeds 0.2 vacil_HMS |

In 3.3.0 several of them lived elsewhere (`metrology/correlation.py`,
`psychoacoustics/tone_audibility.py`); the package import is the answer there
too.

`signals.test_signals` (4.0.0rc1) is private as well, for another reason:
pytest collects a module whose name starts with `test_`, and the prefix belongs
to test files. Every function it held keeps its `signals.` address, so `from
phonometry.signals.test_signals import noise_signal` is `from
phonometry.signals import noise_signal`.

The type aliases those modules defined went with them, and no public path
reaches them now: `PrecisionSurface`, `PrecisionArray` and `PrecisionRoom` of
`emission.sound_power_anechoic`, `MicrophoneShield` of
`emission.sound_power_in_duct`, `Grade` and `BandType` of
`emission.sound_power_intensity`, and `DeterminationGrade` and `BandType` of
`emission.sound_power_intensity_points`. Annotate with the `Literal` each stood
for: `Literal["sphere", "hemisphere"]` for `PrecisionSurface`, and so on.
`BandType` named a band set, which is now the integer `fraction`:
`Literal[1, 3]`.

```python
from phonometry import room, signals

print(callable(signals.correlation), callable(signals.time_delay))
print(callable(room.impulse_response), callable(room.mls_impulse_response))
# True True
# True True
```

### And every public module says what it publishes

A module without `__all__` says nothing about which of its names are public,
so a constant it defined for its own use looked as public as its functions,
and some of them reached guides and scripts through the full module path. Every
public module now lists what it defines and its package publishes, and anything
else it defines takes a leading underscore. These names were reachable that
way in 3.3.0 or 4.0.0rc1 and are not any more:

| 3.3.0 or 4.0.0rc1 | 4.0 |
| --- | --- |
| `OCTAVE_BANDS`, `NC_INDICES` and `NC_CURVES` of `room.noise_criteria` (`room.room_noise` in 3.3.0) | `room.NC_OCTAVE_BANDS_HZ`, `room.NC_RATINGS` and `room.NC_CURVE_LEVELS`, published with their unit: the ten bands of ANSI/ASA S12.2 Table 1, its twelve designations and their band levels |
| `BAND_CENTERS`, `BAND_IMPORTANCE`, `REFERENCE_INTERNAL_NOISE` and `VOCAL_EFFORTS` of `speech.sii` (`hearing.sii` in 3.3.0) | `speech.sii_procedure("one-third-octave")`, whose `frequencies`, `band_importance` and `internal_noise` are the same arrays, and `speech.standard_speech_spectra().vocal_efforts` |
| `NIPTS_FREQUENCIES` of `hearing.noise_induced_hearing_loss` | the `frequencies` of the `hearing.nipts(...)` result |
| `VALIDATED_YEARS`, `VALIDATED_FRACTILES` and `VALIDATED_L_EX_MAX` of the same module | not published. `nipts` and `htlan` warn outside the 1 to 40 years, the 0.05 to 0.95 fractiles and the 100 dB ISO 1999 validates |
| `OCTAVE_BANDS` of `noise_control.hvac` and of `room.enclosed_space_absorption` | not published: each is the default band axis of its functions, and every result carries its `frequencies` |
| `SPEED_OF_SOUND`, `AIR_ATTENUATION` and `PUBLISHED_AIR_CONDITION` (`DEFAULT_AIR_CONDITION` in 3.3.0) of `room.enclosed_space_absorption` | not published: the 345.6 m/s default of `speed_of_sound=`, and the six conditions `air_condition=` takes, which its docstring lists, `"20C_50-70"` the one clause 4.3 recommends |
| `REFERENCE_VELOCITY`, `REFERENCE_FORCE`, `REFERENCE_SOUND_POWER` and `FREE_VELOCITY_REFERENCE` of `building.measurement.structure_borne_power` (`building.structure_borne_power` in 3.3.0), and `REFERENCE_PRESSURE` of `environment.assessment.impulsive_sound` (`environmental.impulsive_sound` in 3.3.0) | the `.value` of the `metrology.REFERENCE_VALUES` entry each was read from, since the entry is a record and not a number: `["solid"]["velocity"].value` (1 nm/s), `["solid"]["force"].value` (1 µN), `["gas"]["sound_power"].value` (1 pW), `["solid"]["velocity_alternative"].value` (the 50 nm/s of note b of Table 3, the ISO 9611 free-velocity reference) and `["gas"]["sound_pressure"].value` (20 µPa) |

| `SPEED_OF_SOUND`, `AIR_DENSITY`, `REFERENCE_FREQUENCY`, `REFERENCE_LENGTH` and `MAX_RADIATION_FACTOR` of `building.prediction.detailed_model` | not published. The air is `building.EN12354_AIR`, which carries the 340 m/s and the 1.29 kg/m³ |
| the coefficients, limits and defaults of `environment.assessment.impulsive_sound` (`environmental.impulse_prominence` and `environmental.impulsive_sound` in 3.3.0): `PROMINENCE_COEFFS`, `ADJUSTMENT_SLOPE`, `ADJUSTMENT_THRESHOLD`, `ONSET_RATE_LIMIT`, `DEFAULT_ASSESSMENT_PERIOD_MIN`, `ONSET_GRADIENT_LIMIT`, `TIME_WEIGHTING_F_TAU`, `MERGE_GAP`, `SAMPLE_INTERVAL_RANGE`, `DEFAULT_SAMPLE_INTERVAL`, `HIGHLY_IMPULSIVE_LIMIT` | not published: each is applied by `impulse_prominence` or `impulsive_sound_adjustment`, and the two defaults are those of `dt=` (20 ms) and `assessment_period_minutes=` (30 min) |
| the Annex C constants of `vibration.human.multiple_shock` (`vibration.multiple_shock_vibration` in 3.3.0): `MZ_MALE`, `MZ_FEMALE`, `DOSE_AMPLITUDE_FACTOR`, `DOSE_EXPONENT`, `GRAVITY`, `ULTIMATE_STRENGTH_INTERCEPT`, `STRENGTH_AGE_SLOPE_MALE`, `STRENGTH_AGE_SLOPE_FEMALE`, `WEIBULL_MALE`, `WEIBULL_FEMALE`, `RISK_THRESHOLDS_MALE`, `RISK_THRESHOLDS_FEMALE` | not published: the functions take `sex=` and apply the pair it names. `compression_dose(..., mz=)` defaults to 0.029, the male value of Formula C.2; pass 0.025 for the female one |

| `WALL_ORDER` of `room.image_source` | not published: a per-wall `absorption=` is in the order `x0`, `xL`, `y0`, `yL`, `z0`, `zL` |

are not listed either, by the rule above, and stay importable as annotations.

```python
print(round(speech.sii_procedure("one-third-octave").band_importance.sum(), 6))
print(hearing.nipts(95.0, 40.0, 0.9).frequencies[:3])
```

## Every `.plot()` takes the axes first

Every result's `.plot()` now reads `plot(ax=None, *, ...)`: the axes first,
and every other argument by name, `language` included. Three did not start
with the axes in 3.3.0, so `plot(ax)` on them handed the axes to the wrong
parameter:

| 3.3.0 | 4.0 |
| --- | --- |
| `LoudspeakerCharacteristics.plot("impedance", ax)` | `.plot(ax, quantity="impedance")` |
| `MicrophoneCharacteristics.plot("noise", ax)` | `.plot(ax, quantity="noise")` |
| `TransferMatrix.plot(f, rho_c, ax)` | `.plot(ax, frequencies=f, characteristic_impedance=rho_c)` |

Six results that are newer than 3.3.0 took `language` by position in
4.0.0rc1: the four hearing-protector ratings and the two low-frequency
intensity results. `plot(ax, "es")` on those is `plot(ax, language="es")`
now, as it is everywhere else.

The public `plot_*` helpers, which draw a device or a geometry rather than a
result, share one shape now as well: what they draw by position, and the
axes, the language and the style keywords by name,
`plot_x(<data>, *, ax=None, ..., language="en", **kwargs)`. Seventeen took the
axes after their data and six took them first. `plot_silencer_geometry` also
took every dimension as a keyword of its own; it takes the `kind` and the
`geometry` a `ReactiveSilencerResult` keeps now, the dimensions in one mapping
under the same keys, so the drawing reads like the result:

| 3.3.0 or 4.0.0rc1 | 4.0 |
| --- | --- |
| `vibration.plot_plate_geometry(0.8, 0.6, ax)`, `environment.plot_barrier_geometry(ax, source_height=...)` and the other twenty-one public `plot_*` helpers | `plot_plate_geometry(0.8, 0.6, ax=ax)`, `plot_barrier_geometry(ax=ax, source_height_m=...)` |
| `noise_control.plot_silencer_geometry("expansion chamber", ax, length=0.3, chamber_area=0.04, pipe_area=0.01)` | `plot_silencer_geometry("expansion chamber", {"length": 0.3, "chamber_area": 0.04, "pipe_area": 0.01}, ax=ax)` |

## A multi-panel `.plot()` returns a tuple of axes

A `.plot()` that draws more than one panel returns, without `ax`, a tuple of
its axes, the top panel first, where 3.3.0 and 4.0.0rc1 returned a NumPy
array of them. Indexing, unpacking and `len()` work as before; the array's
own attributes do not:

| 3.3.0 or 4.0.0rc1 | 4.0 |
| --- | --- |
| `axes = result.plot()`, then `axes.shape` or `axes.size` | `len(result.plot())` |
| `result.plot().flat`, `result.plot().ravel()` | the tuple itself: `for ax in result.plot()` |
| `isinstance(drawn, np.ndarray)`, to tell several panels from one axes | `isinstance(drawn, tuple)` |

With `ax` the plot draws one panel on it and returns that axes, as before.
Each case is a typed overload now, so a type checker reads
`top, bottom = result.plot()` as two `Axes` and `result.plot(ax=ax)` as one.
`ZwickerLoudness.plot()` without `ax` still returns one axes for a stationary
result and two for a time-varying one, which only the data decide.

The plots that draw on a polar axes say so. `PistonDirectivity`,
`VectorChangeResult` and `DiffuserPolarResponse` return a `PolarAxes`, and so
do `DiffusionResult.plot()` without `ax`, `DirectivityFactor.plot()` for its
`"response"` view, and `LoudspeakerCharacteristics.plot()` and
`MicrophoneCharacteristics.plot()` for `quantity="directivity"`. Those take a
`PolarAxes` where they need one; matplotlib types a subplot made with
`projection="polar"` as plain `Axes`, so a typed caller hands it over as
`typing.cast(PolarAxes, ax)`. `DiffuserPolarResponse.plot()` refuses a
cartesian axes with a `ValueError` that names `ax`, as the other polar plots
do, where it raised an `AttributeError` from matplotlib.

## Verdicts are result objects, not dictionaries

The three `verify_*` functions of 3.3.0 returned `dict[str, Any]` and now
return a frozen dataclass, like every other result in the library.
`filter_class_compliance`, the public wrapper that existed only to package the
filter verdict, went with the change, since the verifier now returns the
object itself. Each key of the dictionary is an attribute of the same name,
but for `passed`, which is `passes`, and every argument after the one the call
is about is written by name.

| 3.3.0 | 4.0 |
| --- | --- |
| `verify_filter_class(bank)["overall_class"]` | `filters.verify_filter_class(bank).overall_class` |
| `verify_filter_class(bank, 4096)` | `filters.verify_filter_class(bank, n_points=4096)` |
| `verify_weighting_class(wf)["overall_class"]` | `filters.verify_weighting_class(wf).overall_class` |
| `verify_aircraft_noise_system(...)["passed"]` | `aircraft.verify_aircraft_noise_system(...).passes` |
| `filter_class_compliance(bank)` | `filters.verify_filter_class(bank)`, which returns the same `FilterComplianceResult` |

`verify_intensity_class` and `verify_quasi_peak_dynamics` are newer than
3.3.0, and in 4.0.0rc1 they already returned their records.

```python
from phonometry.filters import OctaveFilterBank, verify_filter_class

verdict = verify_filter_class(OctaveFilterBank(48000, fraction=1, limits=[125, 4000]))
print(verdict.overall_class, len(verdict.bands))
```

`verify_running_rms_decay` is newer than 3.3.0, and in 4.0.0rc1 it returned a
bare `bool`, which threw away the printed interval and the measured time it
had judged. It now returns a `RunningRMSDecayVerification` that keeps both:
the verdict is `.passes`, beside `.measured_time_s`, `.printed_time_s`,
`.tolerance_s` and the interval as `.lower_time_s` and `.upper_time_s`. The
object refuses to be read as a truth value, so an
`if verify_running_rms_decay(...):` written against the release candidate
raises `TypeError` instead of passing every meter.

## A verdict says `passes`, refuses a truth value, and comes from a verb

A judgement is named for what it judges: `verify_` an instrument, `assess_` a
measured situation, `check_` the setup a method needs. Each returns a record
that keeps its reasons, and a pass or a fail is spelled `passes` on every one of
them. A record a judging function returns, and every record with a `passes`,
refuses to be read as a truth value: `if verdict:` raises `TypeError` and the
message names what to read. In 3.3.0 and 4.0.0rc1 these records were always
true, so an `if` written against them passed every failure: read `.passes` on
`QuasiPeakDynamicsResult`, `AircraftSystemComplianceResult`,
`WeightingVerification`, `PhaseVerification`, `SignalBurstVerification`,
`DBHRCheck`, `DBHRAssessment`, `ActivityAssessment` and `PeriodAssessment`;
`.overall_class` on `FilterComplianceResult`, `WeightingComplianceResult` and
`IntensityInstrumentComplianceResult`; `.within_guideline` on
`DamageAssessment`, since exceeding a guideline value of DIN 4150-3 is not a
failure; `.qualified` on `PrecisionCriteria`; `.adjustment` on
`TonalAssessmentResult`; and `.decisive_audibility` or `.audible` on
`ToneAudibilityResult`.

| 3.3.0 or 4.0.0rc1 | 4.0 |
| --- | --- |
| `.complies` on `DbHrCheck`, `DbHrAssessment` (now `DBHRCheck`, `DBHRAssessment`), `ActivityAssessment` and `PeriodAssessment` | `.passes` |
| `vibration.is_significant_change(change, zone_b_upper)` | `vibration.assess_operational_change(change, zone_b_upper).significant`, beside the `.threshold` it is read against. A significant change is a reason to investigate, not a failure, so the flag keeps its name |
| `materials.limp_frame_applicable(k_c, criterion=...)` | `materials.check_limp_frame(k_c, criterion=...).passes`, beside the `.ratio` and the `.threshold`. A ratio exactly on the threshold no longer passes: Allard & Atalla print both criteria as strict inequalities |
| `fi.field_is_stationary(limit=...)` on a `FieldIndicators` | `fi.check_field_stationarity().passes`, and band by band its `.stationary`. The limit is the 0.6 of Table B.3, read as `.limit`, and no longer an argument |
| `room.perceptibly_different(symbol, first, second)` | `room.assess_perceptible_difference(symbol, first, second).different`; the two values must now have the same shape |
| `materials.check_base_plate_scattering(s) == ()` | `materials.check_base_plate_scattering(s).passes`, with the bands over the limit in `.exceeded_frequencies` and the per-band `.margins`, `.exceeds` and `.limits` beside them. A coefficient that is not finite raises `ValueError`, where it used to pass |
| `corrected, limited = building.background_corrected_level(lp, lb)` | `result = building.background_corrected_level(lp, lb)`, then `result.corrected_levels` and `result.limited` |
| `k1, held = emission.background_noise_correction_at_workstation(lp, lb)` | `result = emission.background_noise_correction_at_workstation(lp, lb)`, then `result.correction` and `result.upper_bound` |

The 3.3.0 top-level names this renames (`rigid_mass_calibration_check`,
`satisfies_lower_requirement`, `satisfies_upper_requirement`,
`strong_coupling_satisfied` and `tonal_seeking_survey`) are in the table of
the names that are gone, at the end of this page.

```python
from phonometry import building, materials

conformity = building.assess_requirement_conformity(52.0, 1.5, 50.0, bound="minimum")
print(conformity.passes, conformity.margin_db)
# True 0.5
check = materials.check_base_plate_scattering([0.02] * len(materials.BASE_PLATE_BANDS_HZ))
print(check.passes, check.exceeded_frequencies.size)
# True 0
try:
    bool(check)
except TypeError as error:
    print(type(error).__name__)
# TypeError
```

## The filter bank returns a result, not a tuple

`octave_filter()` and `OctaveFilterBank.filter()` returned two items normally
and three when `sigbands=True` asked for the band waveforms. The length of the
answer depended on a keyword, which is why the pair needed twelve `@overload`
declarations to be typed at all, and why `_, _, bands = bank.filter(...)` was
a line you had to count commas in.

They now return an `OctaveFilterResult` with named fields. The other answers
of the bank that were tuples are records too: the spectrogram is an
`OctaveSpectrogramResult`, and the band set the bank is designed on is read
from attributes spelled out in full.

| 3.3.0 | 4.0 |
| --- | --- |
| `spl, freq = octave_filter(x, fs)` | `r = octave_filter(x, fs)`, then `r.levels` and `r.frequencies` |
| `spl, _ = octave_filter(x, fs)` | `octave_filter(x, fs).levels` |
| `_, freq = octave_filter(x, fs)` | `octave_filter(x, fs).frequencies` |
| `_, _, bands = bank.filter(x, sigbands=True)` | `bank.filter(x, sigbands=True).require_bands()` |
| `levels, freq, times = bank.spectrogram(x)` | `r = bank.spectrogram(x)`, then `r.levels`, `r.frequencies` and `r.times` (an `OctaveSpectrogramResult`, drawn with `r.plot()`) |
| `bank.freq`, `bank.freq_d`, `bank.freq_u`, `bank.nominal_freq`, `bank.num_bands` | `bank.frequencies`, `bank.lower_edges`, `bank.upper_edges`, `bank.labels`, `bank.n_bands`, read-only: the arrays refuse writes and `labels` is a tuple |

```python
import numpy as np
from phonometry import filters

result = filters.octave_filter(np.zeros(8000) + 1e-6, 8000, fraction=3)
print(len(result.frequencies), result.bands)
# 25 None
```

`bands` is `None` unless the call asked for `sigbands=True`, and `levels` is
`None` for a call made with `calculate_level=False`. Code that needs either
one can say so with `require_bands()` or `require_levels()`, which return the
value or raise naming the argument that was missing, rather than handing back
a `None` that fails several lines later.

The result also draws itself, so the band spectrum is one call:

```python
ax = result.plot()
```

## Other answers that were tuples are records

Every other answer that came back as a tuple of different quantities, to be
unpacked by position, is a record with named fields now, and none of them
unpacks: a line that still does raises `TypeError: cannot unpack

## Tolerance limits come lower first, and signed

`vibration.weighting_tolerance_percent` returned the Table 5 band of
ISO 8041-1 as `(upper, lower)`, and the three constants
`CENTRAL_TOLERANCE_PERCENT`, `SKIRT_TOLERANCE_PERCENT` and
`TAIL_TOLERANCE_PERCENT` held `(upper %, lower %, phase °)`. Every other pair of
limits in the library is `(lower, upper)`, so these two now are too. The lower
limit stays negative, as the table prints it, and `-100.0` still means that
the standard sets no lower limit.

This one changes no name and raises nothing: `upper, lower = ...` still
unpacks two arrays, and swaps them. Read every unpacking of the four:

| 4.0.0rc1 | 4.0 |
| --- | --- |
| `upper, lower = vibration.weighting_tolerance_percent(name, f)` | `lower, upper = vibration.weighting_tolerance_percent(name, f)` |
| `vibration.CENTRAL_TOLERANCE_PERCENT == (12.0, -11.0, 6.0)` | `(-11.0, 12.0, 6.0)` |
| `vibration.SKIRT_TOLERANCE_PERCENT == (26.0, -21.0, 12.0)` | `(-21.0, 26.0, 12.0)` |
| `vibration.TAIL_TOLERANCE_PERCENT == (26.0, -100.0, inf)` | `(-100.0, 26.0, inf)` |

```python
from phonometry import vibration

lower, upper = vibration.weighting_tolerance_percent("Wk", [16.0])
print(lower, upper)
# [-11.] [12.]
```

## A record's fields are required

Several records carried fields that defaulted to `None`, so that a result
built by hand from a few of its numbers would still construct. Every reader
then had to ask whether the field was there: the fiche refused a bare rating
only once a report was asked for, and a plot of the geometry raised that the
result "does not retain its geometry". The fields are required now, and a
record built without one, or with `None` for one (`dataclasses.replace`
included), raises `TypeError` naming it.

| Record | Required now |
| --- | --- |
| `building.AirborneInsulationResult` | `l1`, `l2`, `t2`, `t0` |
| `building.ImpactInsulationResult` | `li`, `t2`, `t0` |
| `building.WeightedRatingResult`, `building.ImpactRatingResult` | `frequencies`, `measured`, `shifted_reference` |
| `building.ExtendedWeightedRatingResult`, `building.ExtendedImpactRatingResult` | `frequencies`, `measured` |
| `building.ApertureTransmissionResult` | `depth`, now the fourth field; and `width_m` for a slit or `radius` for a circular aperture |
| `building.FacadePredictionResult` | `elements`, now the sixth field |
| `emission.IntensityResult` | `spacing_m`, keyword-only |
| `environment.BarrierInsertionLoss` | `source_height_m`, `barrier_distance`, `barrier_height_m`, `receiver_distance`, `receiver_height_m`, keyword-only |
| `psychoacoustics.ZwickerLoudness` | `field` (`"free"` or `"diffuse"`), now the fourth field, before `n5` |
| `room.OpenPlanResult` | `positions_m`, the distances the metrics were fitted on |
| `materials.LayeredAbsorberResult` | `layers`, the stack the prediction was solved for |
| `materials.DiffuserPolarResponse` | `well_width` and `n_repetitions`, keyword-only; `depths` stays optional, because a response predicted from an explicit `reflection` has none |
| `materials.MetadiffuserResult` | `wells`, `depth_m` and `period_m`, the panel the reflection was solved for, keyword-only |
| `materials.SlitResonatorAbsorberResult` | `resonators`, `slit_height_m`, `lattice_step_m` and `period_m`, the panel the prediction was solved for, keyword-only |
| `materials.ImpedanceTubeResult` | `spacing_m` and `x1`, the microphone spacing and the distance from the sample to the farther microphone, which the reduction cannot run without, keyword-only; `diameter_m` stays optional, because it need not be supplied |
| `materials.InSituAbsorptionResult` | `source_height_m` and `microphone_height_m`, the set-up the absorption was measured with, keyword-only |
| `vibration.JunctionTransmissionResult` | `thickness1_m` and `thickness2_m`, the plates of the junction, keyword-only |
| `noise_control.ReactiveSilencerResult` | `plane_wave_limit`, and exactly one of `geometry` (a named device) and `chain` (a `SilencerChain`); `resonances`, `geometry`, `plane_wave_limit` and `chain` are keyword-only |

`simulation.FDTDResult` and `simulation.ElasticFDTDResult` take two more
fields, after the others: `snapshot_decimation`, every how many cells a
snapshot keeps along each axis (1 for every cell, as before), and
`provenance`, the `simulation.RunProvenance` of where the run stepped. A
result built by hand passes both, and leaving one out raises `TypeError`
naming it; the results the simulation functions return carry both already.

`filters.WeightingFilter(..., high_accuracy=None)` used to select the
default. `high_accuracy` is a plain `bool` now, `True` by default, and `None`
raises `TypeError` rather than being read as false, which would pick the plain
design.

`building.CeilingAttenuationResult.rounded` was a field the caller passed in.
It is read from `measured` now, rounded to the nearest integer as ASTM E413
clause 5.2 asks (the clause leaves a half open, and the library rounds
it up), so it cannot disagree with the data;
leave it out when building the record by hand.

## Waveforms inside results come back as the `Signal` they came from

A transform handed a `Signal` has returned a `Signal` since the contract was
written, but five result objects still stored their waveform as a bare array
next to a loose `fs`. They now keep the type the input arrived as:

| Field | Is a `Signal` when the input was one |
| --- | --- |
| `envelope(...).signal` | at the input's rate |
| `time_synchronous_average(...).period_waveform` | at the input's rate |
| `resample_signal(...).signal` | at `fs_new`, which then has to be a whole number of hertz |
| `align_impulse_responses(...).aligned`, `.reference` | each one if its own input was |
| `underwater.pile_strike_metrics(...).pressure` | at the input's rate |

A bare array in still gives a bare array out, so code that passes arrays does
not notice. Code that passes a `Signal` and does arithmetic on one of these
fields goes through `np.asarray`, as it does for any `Signal`, and a
calibrated input comes back with `calibration_factor=1.0`, so the field feeds
the next function in pascals without the factor being applied again.

## A block stream yields `Signal` blocks

`io.read_blocks` is newer than 3.3.0, and in 4.0.0rc1 it yielded bare float64
arrays. It now yields a `Signal` per block, carrying the rate, the
calibration, the channel labels and the provenance `io.read` gives, and it
takes the same `calibration_factor=` and reads the same sidecar. Two things
change for a loop written against the release candidate. A block from a
calibrated file reaches the filters and the level functions in pascals, so a
`calibration_factor` applied by hand on top of it counts twice. And
arithmetic on a block, or on what a filter returns for one, goes through
`np.asarray`, as it does for any `Signal`.

## Published tables refuse writes

Every table the library publishes at module level is read-only in 4.0. In
3.3.0 published tables were plain dictionaries and published arrays took
in-place arithmetic, so a line such as `REFERENCE_CURVE[500] = 0.9` or
`BAND_IMPORTANCE *= 2` changed the number for every caller that ran after it
in the same process, and nothing raised. The dictionaries are now
`types.MappingProxyType`, including the ones nested inside another table, and
the arrays have their `writeable` flag cleared. Reading is unchanged; writing
raises `TypeError` on a table and `ValueError` on an array.

Code that adjusted a published table has to copy it first:

```python
from phonometry import room
from phonometry.materials.absorbers import REFERENCE_CURVE

curve = dict(REFERENCE_CURVE)
curve[4000] = 1.0
curves = room.NC_CURVE_LEVELS.copy()
curves[0, 0] = 0.0
print(REFERENCE_CURVE[4000], curve[4000], curves[0, 0], room.NC_CURVE_LEVELS[0, 0])
# 0.9 1.0 0.0 78.0
```

A table with tables inside it needs each level copied, as in
`{area: dict(rows) for area, rows in GUIDE_VALUES.items()}`. The same copy is
needed before a table is pickled, deep-copied or written out as JSON, because
a read-only mapping supports none of the three.

## A result keeps its own copy of the arrays it was given

In 3.3.0 and in 4.0.0rc1 a result kept the very array it was handed whenever
that array was already of the type the function reads, `float64` for levels
and frequencies, because `np.asarray` hands its argument back unchanged in
that case. Changing the caller's array afterwards, `levels[0] = 0.0` or
`frequencies *= 2`, changed a result already computed and perhaps already
printed. In 4.0 every array that a function or a method of the library
keeps from the arguments it was given is a copy of its own, made read-only
like the published tables, and the caller's array is left as it was. That
holds for the objects that keep arrays to hand out later as well: the
frequency grid of a `noise_control.SilencerChain`, the axes and flight paths
an `aircraft.ANPDatabase` is built from, and the medium maps of
`simulation.FDTD2D` and `simulation.ElasticFDTD2D`, whose `c`, `rho`, `c_p`
and `c_s` now stay the ones the time step was computed from. The maps the
engines derive from them, `FDTD2D.kappa` and `ElasticFDTD2D.mu` and `.lam`,
are read-only NumPy copies too: in 4.0.0rc1 an edit to one reached part of the
step and not the time step, and now it raises `ValueError`, so a different
medium is a new engine built from edited maps. A `Signal`
keeps a copy of its own samples too, which stays writeable for processing in
place, as the samples of a file read with `io.read` always were. A result
record built by hand, by calling its class directly, makes the same copy:
every public record that can hold an array copies the arrays it is handed
when it is built, whoever builds it, also inside a tuple, a list or any
mapping. A record held inside another one is kept whole and answers for its
own arrays, and a `Signal` is no exception: the seven results that hand a
waveform back as a `Signal` (`filters.OctaveFilterResult`,
`signals.EnvelopeResult`, `signals.ResampledSignalResult`,
`signals.AlignedImpulseResponseResult`, `signals.SynchronousAverageResult`,
`environment.DirectSoundSubtraction` and `underwater.PileStrikeResult`) hold
one of their own when the library builds them, whose samples stay writeable
like any `Signal`'s, and hold the caller's own when built by hand around it.
Every other array a result holds refuses in-place writes, the ones it
computed as well as the ones it was given, where in 3.3.0 most computed
arrays took them. Writing into one now raises `ValueError`, so code that
edited one in place has to copy it first:

```python
import numpy as np

from phonometry import io, room

levels = np.array([60.0, 58.0, 55.0, 52.0, 50.0, 48.0, 45.0, 42.0, 40.0, 38.0])
nc = room.noise_criterion(levels)
levels[0] = 0.0
samples = np.zeros(4)
signal = io.Signal(samples, fs=48_000)
samples[0] = 1.0
measured = np.array([1.0, 0.5, 0.25, 0.125])
response = room.ImpulseResponseResult(ir=measured, fs=48_000, method="farina")
measured[0] = 0.0
edited = nc.levels.copy()
edited[0] = 62.0
print(nc.levels[0], nc.levels.flags.writeable, response.ir[0], response.ir.flags.writeable)
print(signal.data[0, 0], signal.data.flags.writeable)
# 60.0 False 1.0 False
# 0.0 True
```

## A catalogue row says what its source claims for each cell

The published catalogues of materials are new in 4.0: neither 3.3.0 nor
4.0.0rc1 had them. They changed shape once on the way to the final release,
and code written against the main branch in between needs the changes below.
Every row of every catalogue now shares one base, `io.CatalogueRow` (with
`io.BandedRow` for a row that prints one value per band), and the same three
questions have the same answer on any of them.

| Before | 4.0 |
| --- | --- |
| `SolidMaterial.estimated`, `OrthotropicWood.estimated` | `row.basis`, which maps each footnoted field to `"estimated"` |
| `SolidMaterial.is_estimate(field)`, `OrthotropicWood.is_estimated(field)` | `row.basis_of(field) == "estimated"` |
| `row.is_derived(field)` on a value the page gives in a unit the row does not hold (the °F and psi of Ver & Beranek Table 14.1, the sabins of Long Table 7.1) | `field in row.converted`; `row.converted[field]` is the page's figure and its unit, such as `("3e5", "psi")` |
| `row.is_derived(field)` on a value the page gives by reference to another of its rows: a cell left blank under a block (Ver & Beranek Table 8.7, ASHRAE Table 30) or a description that reads "Parecido al anterior" (Harris Chapter 32) | `field in row.carried`; `row.carried[field]` names the row |
| `OrthotropicWood(...)` and `PlateauMaterial(...)` with their own fields by position | every field by name, as on every other row |
| `from phonometry._internal.catalogue import CatalogueRow` | `from phonometry.io import CatalogueRow` |

`is_derived` now answers only for what the library computes and could compute
again from the row's own cells, such as a bar speed worked out from a modulus
and a density. A value the page gives in another unit is still the page's
number, and so is one it gives by reference to another of its rows, so neither
is derived any more. `basis_of` answers with the field's own entry, else the
row's, else an empty string, which means the source does not say how the
number was obtained; the five things a source can claim are in
`io.CATALOGUE_BASES`.

```python
from phonometry import solids

board = solids.PUBLISHED_SOLIDS["hopkins-2007-table-a2/plasterboard_natural_gypsum"]
ear = solids.damping_named("EAR C-1002")[0]
print(board.basis_of("poisson_ratio"))
# estimated
print(ear.converted["youngs_modulus_max_pa"], ear.is_derived("youngs_modulus_max_pa"))
# ('3e5', 'psi') False
```

The resilient layers became catalogue rows in the same change. A
`ResilientLayer` is an `io.CatalogueRow` like every other row, keyed and
credited the way the others are:

| Before | 4.0 |
| --- | --- |
| `PUBLISHED_RESILIENT_LAYERS["mineral_wool_rock_60_30"]`, `resilient_layer("mineral_wool_rock_60_30")` | `"hopkins-2007-table-a3/mineral_wool_rock_60_30"`, the `"<table>/<row>"` key of every catalogue |
| `layer.attributed_to`, a string | `layer.attributed_to["row"]`, a mapping as on every row |
| `ResilientLayer(...)` with the stiffness, the density and the thickness required | every quantity optional, and `apparent_dynamic_stiffness_n_m3` beside `dynamic_stiffness_n_m3` for a source that gives only the apparent $s'_\mathrm{t}$ |
| `layer.natural_frequency(mass_per_area=...)` | `layer.natural_frequency(mass_per_area_kg_m2=...)`; a layer that holds only $s'_\mathrm{t}$ also takes `airflow_resistivity_pa_s_m2=` and `gas_stiffness_n_m3=`, and raises `ValueError` without the first |

Hopkins Table A3 prints $s'$, the stiffness of the installed layer as the
book's own list of symbols defines it, so its fifteen rows still hold
`dynamic_stiffness_n_m3` and return the natural frequencies they returned
before. Four of them hold a density the page prints once for their block and
leaves blank on their own line, and `layer.carried["density_kg_m3"]` now
names the row that prints it; the density is the same.

```python
from phonometry import materials

rebond = materials.resilient_layer("hopkins-2007-table-a3/rebond_foam_64_20")
print(rebond.attributed_to["row"], round(rebond.natural_frequency(mass_per_area_kg_m2=120.0), 1))
# Hopkins and Hall (2006) 43.6
```

## A catalogue row checks itself when it is built

Every catalogue row is checked in its constructor, whether the library builds
it from a packaged table or a caller builds it by hand, and a cell nothing
downstream could read raises `io.CatalogueError`, naming the row and the
field. Code written against the main branch in between that relied on any of
these being accepted has to change:

| Accepted before | 4.0 |
| --- | --- |
| `NaN`, an infinity, `True` or a text such as `"0,97"` in a numeric field | `CatalogueError`; a cell the page leaves empty is `None` |
| a fraction in a whole-number field (`year`), `1` in a flag field (`has_section_drawing`), a number in a text field | `CatalogueError` |
| an empty `name` or `source`, or a hedge whose text is empty, as in `misprinted={"porosity": ""}` | `CatalogueError`; `why_missing` answered `""` for that cell, which hid the hedge |
| a hedge keyed by a field the class does not have, as in `ranges={"no_such_field": ...}`, or a hedge on a number (`ranges`, `approximate`, `unquantified`, ...) keyed by a text field | `CatalogueError`, naming the hedge and the key |
| `bounded_above` or `bounded_below` on a field with no range; a range, or an interval among the `reported` readings, with an end that is not finite or with its low end above its high one; a `reported` list with nothing in it; an `uncertainty` below zero | `CatalogueError` |
| a value beside `misprinted`, `unquantified`, `not_derivable` or `reported` on the same field; a `converted` or `carried` entry on a field that holds nothing | `CatalogueError`: the first four say there is no value to serve, the last two have nothing to describe |
| a value below zero in a field whose name ends in `_kg_m3`, `_kg_m2`, `_kg`, `_kg_mol`, `_m_s`, `_pa`, `_pa_s_m2`, `_pa_s_m`, `_n_m3`, `_mm`, `_um`, `_m`, `_m2`, `_m_hz` or `_per_cm` (a density, a mass per area, a mass, a molar mass, a speed, a pressure or modulus, a flow resistivity, a specific flow resistance, a stiffness per area, a length, an area, a thickness-frequency product, a count per centimetre); a porosity outside 0 to 1; `shot_content_percent`, `binder_content_percent` or `adhered_area_percent` outside 0 to 100 | `CatalogueError`; a Celsius temperature, a decay rate per metre and a level in decibels stay signed |
| `approximate=[...]` kept as the list it was given, a mapping kept as the dict | a `frozenset`, and every mapping frozen all the way down, its pairs into tuples |
| a subclass field annotated with a type the contract has no check for, a bare `float` or `int` included | `TypeError` the first time the class is built; a field is `float \| None` (`Optional[float]` is the same), `int \| None`, `bool`, `str`, `frozenset[str]` or a `Mapping[str, ...]` of those, because every cell of a row may be missing |
| `PorousMaterial.frame_constants()` on a row without `structural_loss_factor`, read as a frame that dissipates nothing | `ValueError`, saying what the page had in that cell |
| `GroundSurface.porosity` holding 26.9 to 58.1 on six rows of Cox & D'Antonio Table 6.7, which the page prints in per cent in a column of fractions that states no unit | `None`, with `misprinted["porosity"]` quoting the figure the page prints; `why_missing("porosity")` and `printed("porosity")` say so |

## A filter bank's class reads every requirement of IEC 61260-1

`verify_filter_class` graded the Table 1 mask alone. For the 2014 edition it
now also grades the effective bandwidth deviation of 5.12 and the summation of
output signals of 5.16, computed as IEC 61260-2:2016 computes them, and a
band's `class` and the bank's `overall_class` are the strictest class met on
all three. For the 1995 edition it grades the filter integrated response of
4.5.3 and the summation of output signals of 4.9 beside Table 1, as that
edition's clause 5 tests them. In both editions every band is graded at the
bank's input rate up to half of it, so a decimated band is graded on the alias
images its decimation folds onto it, and the bank's decimator keeps them more
than 125 dB down.

| Before | 4.0 |
| --- | --- |
| each band of a decimated bank decimated until its processing Nyquist frequency is 1.25 times its upper band edge | decimated only as far as leaves it sixteen times that edge, so the bilinear transform no longer bends the band: a band level moves by up to 0.07 dB on white noise, most in the lowest bands, and the octave bank, which would sum its outputs up to +0.94 dB and read class 2 on 5.16, is class 1 on every requirement |
| a band's `class` read off `margin_class{c}_db` | `class` over every requirement; `margin_class{c}_db` is still the Table 1 margin, beside `bandwidth_margin_class{c}_db` and `summation_margin_class{c}_db`, which is `None` on the two end bands |
| one requirement to ask about | `requirements`, `requirement_class(name)` and `binding_margin(name, cls)` read each one on its own, and `plot(requirement="summation")` draws it |
| an `edition="1995"` verdict on Table 1 alone | Table 1, `"effective_bandwidth"` (the filter integrated response of 4.5.3) and `"summation"` (4.9, run from the lowest to the highest mid-band frequency, so the end bands carry it too), both at the S that 5.3.3 raises in steps of 12 until the integrated response settles, which the result's `points_per_bandwidth` reports (36 for the default octave bank) |
| a decimated band graded up to the Nyquist frequency of its decimated rate, `checked_to_omega` stopping there | graded at the input rate up to half of it, alias images included; `checked_to_omega` is half the input rate over the mid-band frequency, and `range_limited` marks a Table 1 mask running on past it |
| the anti-aliasing filter `scipy.signal.resample_poly` designs by default, which left the images of the octave bank at 8, 16 and 32 kHz 68.9 dB down, under the 70 dB of class 1 | a filter of the same length sized for a 120 dB stopband, its images at least 125.4 dB down; a band level moves by under 0.01 dB |

The octave and one-third-octave banks keep class 1.

```python

    filters.OctaveFilterBank(48000, fraction=1, limits=[125, 4000]))
print(octave.overall_class, octave.requirement_class("relative_attenuation"))
```

## A verdict reads its printed limit from the standard

A verdict used to carry the limit it was judged against as a constructor
field. In 3.3.0 three did: `ToneAssessment.criterion_db`,
`ExposureAssessment.action_value` and `limit_value`, and
`RigidMassCalibrationResult.tolerance`. Six more that are newer than 3.3.0
did in 4.0.0rc1, and the rest of the table arrived after 4.0.0rc1. Anything
that built one by hand, or rewrote one with `dataclasses.replace`, could
judge a measurement against any number and still print the standard's name
over the result. In 4.0 every limit a standard prints is a read-only
property, read from the fields that select it: the bands, the condition, the
source, the class, the room. A verdict that was stored beside its limit is
read from the measured fields too, or checked against them when the result
is built, so it cannot contradict the limit. The functions that return these
verdicts take the same arguments and give the same answers, and every name
below, in its 4.0 spelling, still reads the same value; only code that constructs a verdict
directly, or replaces one of these fields, has to change. The last column
says where each verdict first shipped.

the specified field strength or the noise measured with the loop off.

## A verdict is read from the values it holds

the advisories, and the class of each band of a filter, weighting or intensity

mapping. The rows of `AircraftSystemComplianceResult.checks`,
`QuasiPeakDynamicsResult.stimuli` and `ReferenceTrackCheck.conditions` are
built from what the result holds and the tables of the standard each time
they are read.

```python

print(gap.passes, round(gap.spread_mm, 1))
# True 0.2
try:
    dataclasses.replace(gap, passes=False)
except TypeError as error:
    print(type(error).__name__)
# TypeError

# False False

```

A flag stays a field where it is no verdict against a limit and nothing the
result holds decides it: an option the caller sets, such as `small_room` or
`noise_is_tonal`; a branch the caller chose by what they gave, such as
`InverseSquareLawResult.origin_fitted`; a fact of an input the result does not
keep, such as `TimeWeightedEnvelope.calibrated`; a property of the file read;
whether an iterative solver converged; and a column of a published table row.
`CriticalCouplingResult.converged` keeps the outcome of its solve, which the
result cannot run again, but it can no longer claim convergence beside an
absorption that does not exceed 0.999, the third condition of the flag.
A regime the result could read from its own values is a verdict, and the next
section lists the ones that moved. `PlantRequirement` and `LoopRequirement` do not change: their rows
keep each limit as a field for the reason the section above gives, and
`PlantRequirement.holds` stays beside it. `TrackCondition` keeps its `holds`
as a row of the report, but `ReferenceTrackCheck` builds its conditions from
the track it holds, so no verdict reads one built elsewhere. The yes/no
`checks` of `SoundLevelMeterPeriodicRequirement` stay as well: they are what
the tester saw, an overload indicated or an indicator latched, not a limit
judged.

## A result reads its regime from the values it holds

Some results stored a regime or a classification beside the values it was
read from: the regime of a valve, whether a hammer rebounds, whether terrain
screens a path, whether a tone was found, whether a synchronous average had to
interpolate. The function compared values the result holds, or could hold,
with a constant or a threshold its source prints, and stored the answer, so a
result built by hand could hold the stiffness of an under-critical hammer and
say it is over-critical. In 4.0 each of them is a read-only property, read
from the values the result keeps, and a result that did not keep what the test
reads now keeps it, with the unit in the name. "By name only" marks a field
that is keyword-only.

A value exactly on a boundary falls where the source puts it. Hopkins prints
the over-critical case as K m ≥ 4 Zdp², so critical damping is over-critical,
and IEC TS 61400-11-2 asks for a total "at least 3 dB" above the background
before the logarithmic subtraction, so a difference of 3 dB takes it.
IEC 60534-8-4 does not settle its cavitation threshold one way: the test of
5.1 leaves the threshold itself to neither side, the region of Equation (9)
and Equation (19b) put it with the cavitating points, and 4.1, Equation (18b)
and 6.3 with the turbulent ones. The library reads it as turbulent, where
Equation (9) returns zero and the two branches meet without a step.

The functions take the same arguments and return the same numbers. Code that
builds one of these results directly, or replaces one of the fields its regime
is read from, has to change, and so does code that reads `fraction` from
`vibration_reduction_index` (see below the table).

| Result | No longer a constructor field | Read from | Since |
| --- | --- | --- | --- |
| `building.TappingForceResult` | `over_critical`, K m ≥ 4 Zdp² (Hopkins Eq. 3.95) | `contact_stiffness`, `impedance`; gains `mass`, by name only | 4.0.0rc1 |
| `noise_control.HydrodynamicValveNoise` | `regime`, cavitating when Δp exceeds x_Fzp1 (p1 - pv) (IEC 60534-8-4 5.1) | `differential`, `corrected_ratio`; gains `inlet_pressure_pa`, `vapor_pressure_pa` | 4.0.0rc1 |
| `noise_control.AerodynamicValveNoise` | `regime`, the five intervals of IEC 60534-8-3 5.2 | `pressure_ratio`, `boundaries`; gains `specific_heat_ratio`, `pressure_recovery`, `efficiency_correction`, by name only | 4.0.0rc1 |
| `aircraft.TerrainScreeningResult` | `screened`, terrain strictly above the line of sight | `source`, `receiver`, `distances_m`, `heights_m` | 3.3.0 |

`building.VibrationReductionResult.fraction` is a field, the band set the
caller states: `octave_bands()` states `fraction=1`, since a single octave band
cannot be told from a one-third-octave band by its spacing.
`vibration_reduction_index` no longer fills it with the band set it read from
the frequencies; it leaves `None`, and the result reads the spacing each time
it takes the Annex A mean, which gives the same mean as before.

The numbers a regime selects are held to it, so a result built by hand can no
longer carry one regime beside the values of another. When it is built, each
of these results refuses:

- `TappingForceResult`: a cut-off frequency, a limiting frequency, a force
  spectrum or a power input that is not what K, Zdp and m give in their
  regime, and limits of Eqs. (3.99) and (3.100) that are not a factor of 2
  apart.
- `HydrodynamicValveNoise`: a vapour pressure at or above the inlet pressure;
  an x_F or an x_Fzp1 that is not what Equation (1) or (3c) gives from the
  fields beside it; a point at or past flashing, x_F = 1; cavitation fields on
  a turbulent point, or none on a cavitating one.
- `AerodynamicValveNoise`: boundaries that are not those of its gas and its
  trim, and a Mach number or an acoustical efficiency of another regime.
- `TerrainScreeningResult`: a source or a receiver that is not a finite point,
  a source at or past the receiver, a section that does not run from one to
  the other, and a path difference or diffracting edges that are not those
  of the rubber band over that section.
- `AutomaticThresholdResult` and `SweepThresholdResult`: reversals that do not
  alternate, a tracing that keeps no peak or no valley, and a mean, a
  threshold or a running threshold that is not what the reversals give.
- `WaveMotionCorrection`: a frequency beyond the last row of Table C.3, and a
  correction the table does not give at its frequency.
- `CabinInsulationResult`: an A-weighted insulation under any method but the
  actual noise.
- `WindTurbineTonalityResult`: a candidate that is not a line of the spectrum
  at or above 20 Hz, and a Formula 30 to 34 chain that is not the one the
  spectrum gives about it.
- `LaboratoryJointInsulationResult`: a corrected index of another rule of J.1.
- `TurbineSoundLevels`: a level difference other than the total less the
  background, a turbine level of another rule of 11.7, and an uncertainty on
  a bin whose level cannot be determined.
- `WestonPropagationResult`: a composite loss that is not the law of the
  regime in force.
- `SynchronousAverageResult`: a period grid other than `round(fs * period_s)`
  samples.

```python
import dataclasses

import numpy as np

from phonometry import building

bands = np.array([100.0, 200.0, 400.0, 800.0])
force = building.tapping_force_spectrum(bands, 1.0e6, 3.0e4)
print(force.over_critical)
# False
print(building.tapping_force_spectrum(bands, 1.0e6, 100.0).over_critical)
# True
try:
    dataclasses.replace(force, impedance=100.0)
except ValueError as error:
    print("cut_off_frequency" in str(error))
# True
```

## A wrong type raises `TypeError`, a missing key `KeyError`, and every warning has a topic

The Python documentation draws the line between the two refusals:
`TypeError` is "raised when an operation or function is applied to an object
of inappropriate type", and `ValueError` "when an operation or function
receives an argument that has the right type but an inappropriate value". In
3.3.0 and 4.0.0rc1 seventy-six refusals asked an argument for its type and
raised `ValueError`, thirty-two more caught a `TypeError` and raised it again
as a `ValueError`, and the shared guards of every scalar parameter refused an
array that way too, while a handful of others raised `TypeError` for the same
mistake. 4.0 raises `TypeError` for a wrong type and `ValueError` for a
right type with a wrong value, everywhere. A call wrapped in `except
ValueError` to absorb any bad input should catch `(TypeError, ValueError)`.

| Passed | 3.3.0 or 4.0.0rc1 | 4.0 |
| --- | --- | --- |
| an array, `None`, a text or an object that is not a number where one number belongs, on any scalar parameter | `ValueError`, and a text that reads as a number, such as `"20"`, was taken as that number | `TypeError`, naming the parameter, for `"20"` and `"fifty"` alike: a text is the wrong type where a number belongs, whatever it reads as |
| an element that is not a number inside an array of numbers (`[None, 1.0]`, `["94.0", "94.1"]`) | `ValueError`, and text numpy reads as numbers was taken as them | `TypeError`, for text whatever it reads as |
| a complex number or array where a real one belongs, on any parameter the shared guards read | `ValueError` | `TypeError`, saying it must be real |
| an array of the wrong kind: a mask that is not boolean (`obstacle_mask=` of `simulation.FDTD2D` and `simulation.fdtd_simulation`, the region masks of `simulation.ElasticFDTD2D.from_regions`, `valid=` of `vibration.band_averaged_stiffness`), `line_counts` of `vibration.BandAveragedStiffness` that are not integers, exclusion flags that are neither booleans nor integers (`excluded_blocks=` of `environment.amplitude_modulation_period`, `excluded=` of `environment.bin_amplitude_modulation`), text where the readings, distances and durations of the service equipment functions of `building` belong (`building.verify_calibration_deviation`, `building.check_background_duration` and the rest) | `ValueError` | `TypeError` |

## What did not change

Most numbers. Every rename above returns what its predecessor returned, except
where this section says otherwise, and if any other result moves after you
finish the upgrade, that is a defect and it is worth
[reporting](https://github.com/jmrplens/phonometry/issues). The numbers that
did move are below. Each moved because 3.3.0 disagreed with the document it
follows, or because a default changed.

`verify_filter_class` grades every requirement of IEC 61260-1 at the bank's
input rate, not the Table 1 mask alone, and a band of a decimated bank moves by
up to 0.07 dB on white noise: the section on filter classes above says how.

The ISO 3382 fiche of a one-third-octave analysis takes its single-number
reverberation time over the six bands from 400 Hz to 1250 Hz, as clause 9.1
prints, where it averaged the 500 Hz and 1 kHz bands. The ISO 10846 fiche of
an indirect determination boxes the stiffness at the lowest line ISO 10846-3
Inequality (2) admits, with a transmissibility of 0.1 or less, where it boxed
the lowest line of the sweep, inside the resonance region. The microphone fiche
writes dB(468) for the ITU-R BS.468-4 weighting, which 3.3.0 let you label
CCIR. A plot draws a band with no reading as no bar, where it drew a measured
zero. Two more are in the sections above: `installed_dynamic_stiffness` below
100 kPa·s/m², and the ISO 3746 survey positions of
`emission.measurement_positions`.

For code written against 4.0.0rc1, the `Signal` contract is the one it was,
now kept in two more places, the blocks of `read_blocks` and the waveforms
inside five results. Every other formula is untouched. 4.0 rearranged the
furniture and put the unit on the label; apart from what this section lists, it
did not recompute anything.
